## 0. Зачем (Job Context)

Платящие репетиторы платят в первую очередь за группы, но **группа не является единицей интерфейса** (боль из PRD мини-групп жива: есть CRUD и ссылка-инвайт после спринта 2026-07-27, но нет «рабочего места группы»). High-level Job из дока 14: «Когда я готовлю учеников к ЕГЭ/ОГЭ и веду сразу нескольких учеников **или группы**, я хочу быстро собирать практику, домашки и объяснения, чтобы ученики стабильно прогрессировали, а я не тратил время на рутину и сохранял контроль над качеством».

**Ядро дизайна:** С1 мини-группы (Елена, Егор — 2–6 учеников, занятия+ДЗ+оплаты). **Stress-тест каждого экрана:** потоки Дианы — 12 групп-литер по 15–25 учеников, массовая выдача, статистика по всем. **Связь с С2 «школа»** (#43, ранг 10; RAT A2 Эмилии): хаб группы — это та самая единица, в которую позже «заходит руководитель» («я в любой момент в класс любого человека могу зайти» — эталон Progressme).

**Инди-ученик = вырожденный случай тех же работ.** Различие одно: нет агрегации «кто из группы» — все остальные звенья (выдать → увидеть в моменте → разобрать → фидбэк → оплата) идентичны и уже живут в карточке ученика (`TutorStudentProfile`). Новых inди-поверхностей эта проработка не вводит; выравнивание — в §5.7.

## 1. КПР: критическая последовательность работ «ведение группы»

Легенда канона: `✅ работает · ⚠️ работает с трением · ⛔ разрыв · ⇄ hand-off · ✨ Aha · ↻ цикл`. Правила: ценность = P(дойдёт до конца) × Outcome − Cost; **один предвидимый разрыв обнуляет цепочку; чиним самое левое сломанное звено; Aha — максимально влево**.

```
Z1 Создать группу ✅
   └─ ManageGroupsSheet/kebab (спринт 2026-07-27, #39 закрыт)
Z2 Собрать состав ✅ / стык ⚠️
   ├─ ссылка саморегистрации в группу (D4) ✅
   ├─ редактор состава ✅
   └─ ⚠️ новый ученик группы НЕ получает уже выданные работы (snapshot-семантика)
Z3 Поставить занятия серией ✅
   └─ unified-занятия + серии до 60 + roster-prompt
Z4 ВЫДАТЬ РАБОТУ ГРУППЕ ⚠️ → ⛔ контекст
   ├─ механика есть (HWAssignSection, вкладка «Группы») ✅
   └─ ⛔ вне контекста группы: из «места группы» выдать нельзя — репетитор
      идёт в конструктор и заново выбирает группу; группа не рабочее место
Z5 УВИДЕТЬ ВЫПОЛНЕНИЕ В МОМЕНТЕ ⛔ ✨ Aha-кандидат
   └─ строка #44 (ранг 12, Эмилия+Елена): «ученик на 5-м вопросе — я уже вижу
      результаты по первым четырём» (эталон Progressme, в т.ч. по группе)
Z6 Разобрать результаты по группе ⛔
   └─ D7 Дианы: только per-ДЗ heatmap; агрегатов «группа × работы / период» нет
Z7 Дать фидбэк группе ✅ / родителям ⇄
   ├─ групповой чат ✅
   └─ ⇄ отчёт родителю есть per-student; группового среза нет (осознанно вне скоупа)
Z8 Получить оплату ✅
   └─ per-participant идемпотентность, баланс-ledger (rule 60)
↻ следующее занятие/неделя → Z3
```

**Диагноз по канону.** Самое левое сломанное звено — **Z4-контекст** (выдача есть, но цепочка рвётся на «где я работаю с группой»: нет места, откуда выдать и куда вернуться смотреть). Следом — **Z5**, и именно Z5 — Aha-кандидат («выдал группе и ВИЖУ, как они решают, не открывая каждого») — его нужно тянуть максимально влево: монитор открывается прямо из подтверждения выдачи. Хаб группы чинит Z4-контекст и даёт поверхность, на которой Z5 и Z6 становятся достижимыми; отдельный экран монитора чинит Z5. Z6 в первой итерации закрывается клиентской агрегацией (см. §6), глубокая аналитика — v2.

## 2. Критерии успеха звеньев (Direction + Level)

По канону job-structure §8: критерий = ось ценности (Direction) + порог (Level), выше которого репетитор чувствует ценность. Прилагательные запрещены.

| Звено | Direction | Level (порог) |
|---|---|---|
| Z1 | Время и число действий до готовой группы | ≤3 действия, ≤30 сек (создать → назвать → готово) |
| Z2 | Ручной труд на добавление ученика | 0 ручных действий: ученик по ссылке попадает в группу сам |
| Z2-стык | Догон новых учеников | новый участник получает активные работы группы ≤1 подтверждением, не N повторными выдачами |
| Z3 | Постановка регулярного занятия | серия на месяц ≤1 действием из хаба группы |
| Z4 | От решения «задам работу» до отправленной группе работы | **≤60 сек** при выдаче из шаблона/Банка; выбор группы не требуется (контекст уже есть) |
| Z4-batch | Прозрачность массовой операции | счётчик «отправлено N из M»; частичный сбой — поимённо + «Повторить для неотправленных»; успешные не откатываются |
| Z5 | Задержка знания «кто где» | вижу построчно «сделал / решает №K / застрял / не открывал» **без открытия каждого ученика, одним экраном, ≤5 сек**; данные не старше 1 мин |
| Z5-сигнал | Точность сигнала «застрял» | «застрял» = ≥3 ошибки или ≥3 подсказки на задаче (существующая эвристика stuck), не «просто медленно» |
| Z6 | Стоимость ответа «как группа справилась» | сводка по группе (средний %, сдали X из Y, слабые задачи) ≤2 тапа из хаба; без экспорта в Excel |
| Z7 | Стоимость сообщения всей группе | чат группы ≤1 тап из хаба |
| Z8 | Видимость долгов группы | долги участников видны в составе (чип), без перехода в «Оплаты» |
| Общий (С2-совместимость) | Проходимость человеком с нулевой цифровой грамотностью | каждый экран проходим без обучения: один основной глагол на экран, узнаваемые названия групп, никакого запрещённого словаря П10 |

**Stress-Level Дианы:** те же пороги обязаны выполняться при 12 группах × 25 учеников: список групп ≤1 экран без поиска (сортировка по ближайшему занятию/активности), монитор 25×10 без горизонтальной прокрутки имени (sticky-колонка), выдача на 25 учеников с progress-состоянием.

## 3. Критерии → метрики (для /admin и решения «UI удался»)

Прямой перевод по канону («критерии переводятся в метрики активации и доставки ценности»):

| Метрика | Формула | Порог успеха | Источник |
|---|---|---|---|
| **Активация групп** | % платящих репетиторов с ≥1 активной группой ≥2 участниками | ≥70% | `tutor_groups`+memberships |
| **Скорость выдачи (Z4)** | median время `group_hub_assign_started → assignment_sent` | ≤60 сек | `analytics_events` (новые события) |
| **Выдача из контекста** | доля групповых выдач ДЗ, начатых из хаба группы (vs конструктор напрямую) | ≥60% через 4 недели | `source_group_id` + событие входа |
| **Aha-монитор (Z5)** | % репетиторов, открывших монитор в первые 30 мин после наступления дедлайна работы | ≥40% недельно | событие `group_monitor_opened` |
| **Возврат в хаб** | WAU хаба группы среди репетиторов с группами | ≥60% | событие `group_hub_opened` |
| **Догон (Z2-стык)** | доля новых участников группы, получивших активные работы ≤24ч после вступления | ≥90% | join событий |
| **Trust batch (Z4-batch)** | fail-rate массовых выдач без поимённого отчёта | 0 (любой сбой виден) | edge-логи |
| Baseline PRD мини-групп §10 | клики «создать группу+состав» vs текущие | −50% | ручной замер по прототипу |

Каждое новое событие — в типизированный реестр телеметрии (PII-free), формулы дублируются в tooltip'ах /admin (rule 101).

## 5. UI-спецификация (по-экранно)

Общие правила (доки 16/17, обязательны): один primary CTA на экран (§11-2); частые действия НЕ в kebab (§11-3); ≤6 видимых элементов в свёрнутой карточке (§11-9); batch — чекбоксы + «Выбрать все» + счётчик + CTA активна при >0 (§6); empty/loading/error/partial-failed у каждого блока (§8.1 + PRD §5); названия = работа, запрещённый словарь П10 (никаких «AI/Smart/Авто»); desktop-first creation, mobile-companion (§10); `// Job:`-комментарий в коде каждого экрана (DoD §14).

### 5.1 Список групп — `/tutor/groups`
- **Job:** «выбрать группу, с которой сейчас работаю» + «увидеть, где требуется внимание, не заходя в каждую».
- Карточка группы (≤6 элементов): цвет+имя, N учеников, ближайшее занятие, активная работа (название + «сдали X/Y»), чип внимания («3 застряли» / «2 долга»), стрелка. **Сортировка: ближайшее занятие → активность.**
- Primary CTA экрана: «Создать группу». Метки — отдельной свёрнутой секцией (это фильтры, не рабочие места).
- Stress Дианы: 12 карточек = один экран без поиска; при >8 группах появляется поиск.
- Empty state: заголовок + одно действие («Создайте первую группу — ученики войдут по ссылке сами»).

### 5.2 Хаб группы — `/tutor/groups/:groupId`
- **Job:** «рабочее место группы: выдать работу, увидеть состояние, вернуться к материалам» (закрывает Z4-контекст).
- **Шапка:** имя (+короткое), состав-аватары + счётчик, чипы «занятие в Ср 18:00», «долги: 2». Действия шапки видимые (не kebab): «Ссылка в группу», «Чат группы». Kebab — только редкое: переименовать, архив.
- **Primary CTA (единственный): «Выдать работу группе»** — открывает флоу 5.5.
- **Блоки** (канон `t-section` как на /tutor/home):
  1. **Сейчас в работе** — активные работы группы: название, дедлайн, прогресс-бар «сдали X из Y», кнопка «Смотреть в моменте» → монитор 5.4. Это верхний блок — Aha влево.
  2. **Занятия** — ближайшие занятия группы (ряд `SessionBlock`), «+ Занятие»/«Серия».
  3. **Работы группы** — история ДЗ/самостоятельных/пробников (существующий `?group_id=`), фильтр по виду работы, у завершённых — сводка «средний % · сдали X/Y».
  4. **Состав** — ученики с чипами статуса (активен/не подключился/долг), «+ По ссылке» и «+ Вручную»; у новичка, вступившего после выдачи — кнопка «Догнать: выдать активные работы» (Z2-стык).
  5. **Результаты** — свод по группе за период: средний % по работам, слабые задачи (клиентская агрегация v1), «Подробнее» → per-ДЗ heatmap.
- Stress Дианы: состав >8 сворачивается в «22 ученика →» (раскрытие списком с поиском); «Работы» пагинируются по 10.

### 5.3 Навигация — оба варианта в макете
- **Вариант A:** пункт «Группы» в SideNav (секция «Ученики», выше «Все ученики»), виден только при ≥1 группе; счётчик внимания.
- **Вариант B:** вкладка «Группы» внутри «Все ученики» (рядом с «Ученики/Успеваемость»).
- Решение — после прокликивания макета. Вне зависимости от варианта: вход в хаб также из kebab секции группы в «Все ученики», из шапки группового занятия в расписании, из бейджа группы на карточке ДЗ.

### 5.4 Монитор выполнения «в моменте» — из хаба, по конкретной работе
- **Job (#44):** «вижу, кто где, пока они решают — реагирую до конца работы» (Z5, Aha).
- Грид ученики × задачи: ✓ сделал (зелёный), число попыток/подсказок (янтарный «решает»), ✗/«застрял» (янтарный с иконкой внимания), «—» не открывал (серый). Sticky-колонка имени (rule 80: `border-separate`), `touch-pan-x`.
- Строка-сводка сверху: «Сдали 3 из 5 · В работе 1 · Не открывали 1».
- Клик по ячейке → мини-панель: последний ответ/вердикт + «Открыть диалог» (существующий drill-down) + «Написать ученику».
- Обновление: авто ≤60 сек (v1 — поллинг существующих results; realtime — v2), индикатор «обновлено N сек назад».
- Псевдо-real-time честен: показываем только события, которые уже есть в БД (сдачи/попытки/подсказки/открытия) — этого достаточно для Level «не старше 1 мин».

### 5.5 Флоу «Выдать работу группе» (из хаба)
- Шаг 1: источник — «Из шаблона» (последние + поиск) / «Из Банка ДЗ» / «Собрать новую» (уводит в конструктор с предвыбранной группой).
- Шаг 2: подтверждение — вид работы (домашка/самостоятельная), дедлайн, список получателей (все N, чекбоксы для исключений), **счётчик «Отправится: N ученикам»**.
- Отправка: progress «N из M», итог поимённо; сбой части — «Повторить для неотправленных» (успешные не откатываются, PRD §5).
- После успеха: CTA «Смотреть в моменте» (мост Z4→Z5, Aha влево).

### 5.6 Мобильная версия
- Companion-режим: список групп и хаб — просмотр + быстрые действия (чат, ссылка, монитор). Выдача работы доступна из шаблона (2 экрана), сборка новой — «продолжите на компьютере» не пишем, просто ведём в конструктор (он mobile-совместим).
- Монитор на мобиле: вертикальный список учеников со статус-чипами вместо грида (грид горизонтально не влезает).

### 5.7 Инди-ученики — выравнивание
- Карточка ученика получает тот же блок «Сейчас в работе» (прогресс активных работ + «Смотреть в моменте» по работе одного ученика) — та же ментальная модель, нулевая новая навигация. Остальное в карточке уже есть.

## 7. Открытые вопросы (к утверждению макета)

1. Вариант навигации A или B (решается прокликиванием).
2. «Сейчас в работе»: показывать все активные работы или последние 3 со свёрткой?
3. Монитор v1 на поллинге 30–60 сек — достаточно для Aha, или realtime обязателен сразу (влияет на объём)?
