## 1. Поворот v0.3 — вопросы стали обычными задачами

Требования Егора и владельца из финального обсуждения: отправка и проверка **по одному вопросу** со своей кнопкой; **своя самостоятельность у каждого вопроса** («видно, с какой попытки ответил»); **свой столбик** в сводной таблице (вариант Б); подсказка снижает самостоятельность **конкретного пункта**; № КИМ — **диапазоном последовательно**; «вопросы можно считать отдельными задачами».

Каждый из этих пунктов — свойство, которое ЗАДАЧА Сократа уже имеет, и которое пришлось бы заново строить внутри «одной задачи с подответами» (свой submit-канал, свой пер-пунктовый `ai_help_events`, пер-пунктовая привязка чата/подсказок — ровно то «отделять пункты для ИИ», которое владелец пометил как проблему). Итог: **«Задание с вопросами» = конструкторная обёртка над группой обычных задач с общим условием** — та же модель данных, что блок (Этапы 1–2 research task-blocks), с UI-обёрткой и четырьмя новыми фичами (§3). Отдельная сущность `sub_answers_json` НЕ создаётся; проверка/тоталы/heatmap/статистика не переписываются.

Слово «блок» из UI ДЗ уходит (просьба Егора «уйти от сущности блок» удовлетворяется терминологически): репетитор видит «Задание с несколькими вопросами», под капотом — группа задач + материал.

| Кирпич | Когда | Механика |
|---|---|---|

| **Задача с критериями** | ученик пишет ОДИН ответ на все пункты (сочинение №27, биология ОГЭ 24–26) | существующий `grading_criteria_json`, без изменений |

## 3. Новые фичи поверх блочной модели (скоуп этой спеки)

1. **Визард «Задание с вопросами» в конструкторе ДЗ**: одна форма (общее условие + вопросы с полями «ответ/формат/балл») создаёт группу задач одним действием. Неделимость: перемещение/удаление/выдача — группой; в списке задач конструктора группа выглядит одной карточкой с разворотом.
2. **КИМ-диапазон как UI-сахар**: поле «№ КИМ первого вопроса» → вопросы получают номера последовательно (26, 27, 28…). **Хранение — по одному КИМ на задачу** (карты режимов/баллов ФИПИ ключуются одиночным номером; диапазон нигде не персистится).
3. **Сводная таблица — групповые колонки (вариант Б, выбор Егора)**: под-колонка на вопрос с баллом + самостоятельностью («как с обычными заданиями» — они и есть обычные); шапка-группа «Задание 3 (а–г)» держит визуальную единицу; **сворачивание группы** кликом в одну клетку-агрегат (сумма + точки-вопросы + средняя самостоятельность), авто-свёртка при >12 колонок таблицы. Это рендер существующих `task_scores` с группировкой по block_id — новых полей в results почти нет (нужен признак группы + подписи а/б/в).
4. ~~Reveal-гейт разбора~~ — **ОТМЕНЁН v0.4** (Егор: «не стоит усложнять: первый пункт — отдельная задача, разобраться до конца, потом дальше»). Дефолт = обычная домашка: разбор ошибки доступен сразу после вердикта; его открытие = `ai_help_events`+1 у этого вопроса — экономика честности уже встроена в метрику самостоятельности, отдельный запрет избыточен. Желание владельца «ничего не раскрывать до завершения» УЖЕ покрыто существующим `work_mode='independent'` (самостоятельная) — новый режим не строим. Остаётся только промпт-инструкция: AI-разбор вопроса N не цитирует верные ответы вопросов N+1 той же группы (+ существующий leak-детектор).

## 4. Что решилось само (и больше не проектируется)

- «По какому пункту снижать самостоятельность при подсказке» — подсказка/чат уже привязаны к конкретной задаче (`task_id`), снижается у неё.
- Пер-вопросная отправка/кнопка — это обычный submit задачи.
- Фото — к заданию целиком остаётся рекомендацией UI (ученик решает а–г на одном листке), но технически фото прикладывается к той задаче, которую сдаёт — как сегодня.
- Развёрнутый вопрос (г) — обычная extended-задача (AI-балл + подтверждение репетитора), никакого «v1.1-режима».
- Анти-спойлер между пунктами: AI-фидбэк задачи б) не должен раскрывать в)/г) — промпт получает список вопросов группы с инструкцией + существующий leak-детектор.

## 5. Открытые хвосты (решить при реализации)

- Олимпиадная классификация: `difficulty === primary_score` считался по задаче; для группы — сложность на обёртке (Банк-метаданные блока), балл — по вопросам. Уточнить с Егором на первом реальном задании.
- Guided-чат: экран группы (все вопросы списком, отправка inline — как в макете v3) vs текущий «одна задача = один экран». Макет предполагает экран группы; это главный UI-кусок Этапа 2.
- ~~«Общее решение» задания~~ — **решено v0.4** (предложение Егора «для каждого вопроса своё решение» — принято): канон = `solution_text`/`solution_image_urls` per задача (уже существует; AI при проверке б) видит решение именно б) — точнее и без лишнего leak-объёма; физ-flowchart-грейдинг и так требует эталон per задача). Плюс удобство ввода: «прикрепить один листок решения ко всем вопросам» — один и тот же storage-ref пишется в `solution_image_urls` каждой задачи группы (ноль новой схемы). Решения tutor-only навсегда (rule 40) — ученик их не видит ни per-вопрос, ни целиком.

## 7. Критерии приёмки (v1.0)

- **AC-1 Визард.** «Задание с несколькими вопросами» в конструкторе ДЗ: общее условие + вопросы (текст, верный ответ/решение, формат проверки, балл) — одно сохранение создаёт группу задач с материалом. Слово «блок» в UI ДЗ не встречается.
- **AC-2 КИМ-диапазон.** Поле «№ КИМ первого вопроса» = N → вопросы получают N, N+1, … последовательно; в БД у каждой задачи одиночный `kim_number`; авто-балл/режимы по картам ФИПИ подхватываются как у обычных задач. Пусто (олимпиада) → без КИМ.
- **AC-3 Неделимость.** Перемещение между папками, выдача, удаление — группой; частичная операция из UI недоступна (внутри визарда вопросы правятся по одному).
- **AC-4 Ученик.** Экран задания: общее условие + вопросы списком, у каждого своё поле и своя кнопка отправки; вердикт ✓/✗ и балл вопроса — сразу; статус-навигация по вопросам. Фото прикладывается к сдаваемому вопросу; подсказка/чат — в контексте конкретного вопроса.
- **AC-5 Разбор.** Разбор ошибки доступен сразу; его открытие инкрементит `ai_help_events` ЭТОГО вопроса (существующий канал). Никакого гейта; экзаменационный порядок = `work_mode='independent'` без изменений.
- **AC-6 Анти-спойлер.** AI-фидбэк/разбор вопроса N получает материал группы и список вопросов, но промпт запрещает раскрывать верные ответы вопросов N+1; leak-детектор действует как обычно.
- **AC-7 Решения.** Эталон per вопрос (`solution_text`/`solution_image_urls` задачи); кнопка «прикрепить один листок ко всем вопросам» пишет один storage-ref в каждую задачу группы. Ученику решения не отдаются никогда (существующий column-GRANT/whitelist инвариант, rule 40).
- **AC-8 Сводная таблица.** Группа задач рендерится под-колонками с шапкой «Задание K (а–г)»; в клетке балл + самостоятельность вопроса (как у обычных задач); клик по шапке сворачивает группу в клетку-агрегат (Σ баллов, точки-вопросы ✓/✗/≈, средняя самостоятельность); авто-свёртка при >12 колонок таблицы. Отчёт родителю и списки ученика получают только существующие агрегаты (ничего нового не течёт).
- **AC-9 Ничего не переписано.** Чекеры, `computeFinalScore`-цепочка, resync тоталов, «% самостоятельности», очередь «Требует проверки», dual write-path — без изменений; вопросы группы проходят по всем этим путям как обычные задачи.
