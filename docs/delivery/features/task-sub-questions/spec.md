# Задание с несколькими вопросами (подответы) — спека v0.1 DRAFT

**Статус:** черновик до валидации макета Егором (решение владельца 2026-08-02: «спека + макет сейчас, реализация — после Этапа 1 блоков»). Макет: `docs/discovery/prototypes/task-sub-questions-mockup.html` (+ артефакт, отправлен владельцу).

Контекст и происхождение — `docs/delivery/features/task-blocks/research.md` §8 («три кирпича»): это НЕ замена блокам и НЕ замена критериям, а третий кирпич — для задач, где несколько ВЗАИМОСВЯЗАННЫХ вопросов с детерминированно проверяемыми ответами составляют одно неделимое задание.

## Section 0: Job Context

- **Job:** Егор (физика, партнёр) готовит олимпиадников. Олимпиадная задача = общее условие + пункты а/б/в с числовыми ответами; пункты взаимосвязаны (б) опирается на а)), решение одно на всю задачу. Сегодня ему приходится либо клеить пункты в одно условие с одним ответом (теряется частичный балл), либо резать на отдельные задачи (рвётся решение, ломается инвариант «сложность = балл», размножается статистика).
- **Wedge:** проверка каждого пункта — кодом, мгновенно и без AI-квоты (экономика структурных тестов); репетитор видит, какой именно пункт валится.
- **Прямой запрос пользователя** (скриншот 2026-08-02): «общее условие → вопрос + поле ответа (формат проверки поля, верный ответ поля) → вопрос + поле…»; неделимость перемещения; самостоятельность на задание целиком. Модель «блок вопросов» Фоксфорда.
- **Почему НЕ ломаем задачу-центричный грейдинг:** разбор с цифрами — research.md §8 (10 подсистем × 2 зеркала). Снаружи это ОДНА задача с одним итоговым баллом; подответы — внутренняя структура её проверки.

## 1. Модель

Расширение механики структурных тестов (`options_json`, rule 40): балл считает КОД, AI только объясняет.

```
homework_tutor_tasks.sub_answers_json  jsonb NULL   -- TUTOR-ONLY колонка (см. §4)
kb_tasks.sub_answers_json              jsonb NULL   -- паритет KB↔ДЗ (unified-task-model)

shape: [{
  key:          "a" | "b" | ...          // стабильный ключ
  label:        "а)"                     // подпись ученику
  question:     string                   // текст вопроса (student-safe)
  correct_answer: string                 // формат tryDeterministicShortAnswerMatch:
                                         //   альтернативы « или », диапазоны «2,1–2,3» — УЖЕ работают
  check_format: "short_answer"           // v1: только краткие; развёрнутые пункты = критерии, не сюда
  max_score:    number                   // шаг 0.5
}]
```

- Задача с непустым `sub_answers_json` → `max_score` задачи = Σ по подответам (derived, в UI read-only «сумма по вопросам»). Валидатор — `isPositiveHalfStepNumber` на каждый подответ.
- Кап: ≤ 8 подответов (реальный максимум пунктов — 3–5); нормализация fail-closed по образцу `normalizeOptionsJson` (битый подответ → отвергается весь `sub_answers_json`, задача остаётся обычной, НЕ обрезается список).
- `task_kind` остаётся выводимым из `check_format` задачи (`numeric`); отдельного kind НЕ вводим (меньше дрейфа словарей).
- **Взаимоисключение:** `sub_answers_json` и `options_json` одновременно — запрещено валидатором. С `grading_criteria_json` тоже (пункт либо детерминированный, либо AI-критерий — смешанные задачи v2).
- **Олимпиадный инвариант сохраняется:** `difficulty === primary_score` считается по ЗАДАЧЕ (= Σ подответов) — пункты не участвуют в классификации.

## 2. Проверка и балл

- Submission: существующий канал (`handleStudentSubmission` / `checkAnswer`) + `submission_payload.sub_values: {a: "3,45", b: "30", ...}` (аддитивное поле JSONB — фронт-тип синхронно, инвариант submission_payload).
- Грейдинг: per-подответ через существующий матчер кратких ответов (альтернативы/диапазоны бесплатно). `earned = Σ max_score[i] × matched[i]`, `deterministic_score = true`, выход строго через `mergeStructuredResult`/`buildStructuredResult`-паттерн (rule 40: любой новый выход из `evaluateStudentAnswer` обязан).
- Вердикт: CORRECT (все), ON_TRACK (часть), INCORRECT (ноль). Пер-подответ ✓/✗ едет в ответ для построчного рендера (см. anti-leak §4: без правильных значений на не-CORRECT).
- AI-квота НЕ тратится на подсчёт; AI-объяснение поверх `precomputedVerdict` — как у структурных тестов; квота исчерпана → canned-фидбэк, не 429.
- Anti-leak объяснения: `feedbackLeaksCorrectChoice`-класс детектора адаптировать (эталоны подответов — полноценные строки, `sanitizeFeedback` применим, но проверить короткие числовые ответы «5» — тот же кейс, что single_choice → детерминированный детектор обязателен).
- «% самостоятельности», force-complete, review, heatmap — НЕ трогаются: снаружи одна задача.

## 3. Скоуп v1 / не в скоупе

**В v1:** ДЗ (оба write-path A/B + kb_snapshot конвертер + шаблоны) · Банк (`kb_tasks` паритет, catalog-safe решение §4) · AI-загрузчик (схема `drafts[].sub_answers`, распознавание «а) б) в)» внутри одной задачи; в ревью — редактор подответов в DraftCard) · экран ученика (см. макет).

**НЕ в скоупе v1 (явно):**
- Пробники (чекеры Части 1 не трогаем; олимпиадных пробников нет).
- Развёрнутые подответы с AI-грейдингом per-пункт (это критерии; смешанный режим — v2 по спросу).
- Вложенность, речевые подответы, пер-подответный override репетитора (правится итоговый балл задачи как сейчас).
- Отдельная запись в `TaskStepper`/шагах — задача остаётся одним шагом guided-чата.

## 4. Anti-leak (3 слоя, rule 40)

1. **Column-GRANT:** `sub_answers_json` на `homework_tutor_tasks` — НЕ гранится authenticated (внутри correct_answer). Ученик получает derived `sub_questions: [{key,label,question,check_format,max_score}]` (без ответов) из student-endpoint'ов (service_role). В `StudentHomeworkTask` тип с ответами не попадает (compile-time слой).
2. `kb_tasks.sub_answers_json` — catalog-safe целиком (Банк tutor/moderator-only, M2b), в column-lists `kb_publish_task`/`kb_resync_task` + resync-условие триггера.
3. Пер-подответный результат на не-CORRECT: отдаём только ✓/✗ и заработанный балл, НИКОГДА правильное значение (пересдача без ограничений — иначе перебор).

## 5. Известные развилки реализации (решить в сессии реализации)

- Имя в UI-селекторе «Формат проверки»: «Задание с несколькими вопросами» (фраза Егора) vs короче «Несколько вопросов (а–в)». Коллизия со словом «Блок заданий» (материал) — в UI НЕ называть это блоком.
- `sub_values` частично заполнены: принимать (незаполненные = 0) или требовать все поля? Дефолт: принимать с confirm «остались пустые поля».
- Диапазон КИМ у задачи (реплика Егора «22–26») — НЕ реализуем: КИМ остаётся одиночным/NULL; подпись диапазона — забота блоков (derived).
