# Что строим
24.07.2026 · для репетиторов ЕГЭ/ОГЭ и руководителей мини-школ · живой продукт, платящий пилот

> ⚠️ Это гипотезы, а не факты — [полный дисклеймер ▸](#disclaimers)

> **Долг валидации:** PRD стоит на **6** непроверенных предположениях, из них **1** фатальное (если неверно — сборка теряет смысл). Проверить фатальное в поле **до** написания кода. [какие ▸](#l2-risk)

## Что строим
Третий вид работы в домашках Сократа — **«Самостоятельная»**: репетитор назначает тот же набор задач, но AI-помощник для ученика выключен (ни подсказок, ни чата) — только сдача ответов и автопроверка. Плюс две честные оценки поверх всех видов работ: **«сколько из скольки баллов»** для ученика и **«% самостоятельности»** (какую долю задач ученик закрыл без подсказок) для обычной домашки. Вторая фаза — AI-сводка «типичные ошибки ученика» по категориям (формулы, чертёж, арифметика…) за работу и за период. [почему именно так ▸](#l2-build)

## Для кого
Репетиторы, готовящие к экзаменам (физика, химия, математика, русский, обществознание — наши платящие), и руководители мини-школ, которые сейчас держат для «нарешивания без подсказок» вторую платформу (CloudText / OnlineTestPad). [кто и почему они ▸](#l2-users)

## Момент, который доказывает, что это работает
Репетитор открывает результаты первой «Самостоятельной» и за минуту видит то, чего не видел никогда: **что ученик умеет САМ** — балл без помощи AI, по каждой задаче, — не потратив ни минуты на проверку и не открывая вторую платформу. [где этот момент в пути ▸](#l2-capabilities)

## Самое рискованное — проверить ДО сборки
Что ученики будут **открывать и сдавать** самостоятельные не хуже, чем обычные домашки. Наше узкое горло — вовлечение учеников; если форма «без AI» не открывается — фича не двигает главную метрику. Проверка дёшево: 2-недельный пилот с Еленой/Егором/Ульяной — назначить по 2 самостоятельные их ученикам, сравнить % открытий/сдач с обычными ДЗ. [полная картина рисков ▸](#l2-risk)

## Что строить первым
Минимальный срез Фазы 1: флаг вида работы + серверное отключение подсказок/чата + одна попытка + экран «Результат работы» для ученика с «X из Y». Без настройки момента разбора (сначала один дефолт — разбор после сдачи работы), без Фазы 2. Этого достаточно, чтобы запустить пилот-проверку рискованного предположения. [полная спека ▸](#l3-requirements)

**Вердикт: GO (to validation)** — строить стоит, но следующий шаг — проверка рискованного предположения в поле на минимальном срезе, а не полная сборка.

<a id="l2-build"></a>
## А строить ли вообще — и почему не «просто пробники»
Мы подняли цель на пять «почему» вверх: фича нужна не сама по себе, а чтобы (1) репетитор видел честную самостоятельность ученика → доверял продукту как инструменту контроля, (2) исчезла причина держать вторую платформу → Сократ стал единственной, (3) ученики чаще заходили в Сократ между уроками — наше узкое горло роста.

Честная альтернатива «ничего не строить»: **пробники уже дают режим без AI** — и Эмилии на созвоне так и предложили. Почему этого мало: пробник несёт экзаменационную обёртку (части, таймер, вёрстка КИМ), не собирается из конструктора ДЗ и Банка в три клика, не крепится к занятию как домашка, не умеет критерии сочинений и произвольные задачи, и его результат живёт в отдельной вселенной от ДЗ-аналитики. Для «двадцати мини-тестов по пять вопросов» и «среза после темы» это стрельба из пушки. Вторая альтернатива-вычитание — дать только «% самостоятельности» без нового режима — закрывает лишь половину Job: срез «что умеет сам» без подсказок она не даёт. Итог гейта: строим режим внутри ДЗ, минимальным срезом. [полный гейт ▸](#l3-challenge)

<a id="l2-users"></a>
## Для кого и момент-доказательство
Репетитор-экзаменщик судит работу по официальным критериям и хочет **видеть разницу между «решил с наставником» и «решил сам»** — это его способ понять готовность к экзамену (его настоящая цель — the Big Job — «ученик сдаёт, я расту в доходе, не тратя вечера»). Сегодня эта разница невидима: в домашке AI помогает всем, а «без помощи» живёт на CloudText/OnlineTestPad. Момент-доказательство (Aha-момент): **первый открытый результат самостоятельной** — репетитор видит балл «сам, без AI» по каждому ученику и каждой задаче, мгновенно. Для ученика свой момент: экран «Результат работы» — «X из Y» и разбор ошибок на его собственной работе сразу после сдачи. [пользователи и цепочка ▸](#l3-overview)

<a id="l2-capabilities"></a>
## Что продукт должен уметь, и почему
1. **Назначать вид работы одним переключателем** в привычном конструкторе — руководитель школы требует простоты для преподавателей «с нулевой цифровой грамотностью»; отдельный флоу убил бы её сегмент.
2. **Честно выключать AI** — на сервере, не только в интерфейсе: срез, который можно обойти из консоли, не срез.
3. **Одна попытка на задачу и разбор после сдачи работы** — иначе это снова тренировка, а не срез; при этом проверка внутри работает сразу (репетитор видит результаты в моменте, ученик — после сдачи).
4. **Показывать ученику итог «X из Y»** — сегодня у ученика вообще нет экрана итогов за работу; для среза он обязателен (и это тот же экран, где живёт разбор ошибок).
5. **Считать «% самостоятельности» в обычных домашках** — данные уже пишутся (счётчики подсказок), нужна только формула и колонка.
6. **(Фаза 2) Называть ошибки по-предметному** — «ошибки в проецировании векторов: 4 за месяц» вместо «wrong_answer» — и сводить в табличку за работу/период. Половина фундамента готова: тип ошибки уже вычисляется при каждой проверке и складывается в таблицу, которую никто не читает. [полные требования ▸](#l3-requirements)

<a id="l2-failures"></a>
## Поломки, которые реально теряют людей
Худшая: ученик открыл самостоятельную, застрял на первой задаче, спросить AI нельзя, выйти страшно — бросил и больше не заходит (лечим: явная плашка правил + пропуск задачи + кнопка «Сдать работу» с пропусками). Вторая: репетитор случайно назначил самостоятельную вместо домашки, ученики остались без подсказок и обиделись (лечим: явный выбор вида + бейджи везде + возможность переключить до первой сдачи). Третья: вердикты «утекли» ученику до сдачи всей работы через API (лечим серверным скрытием по образцу пробников). [вся таблица ▸](#l3-edge)

<a id="l2-risk"></a>
## Самое рискованное предположение — и самая дешёвая проверка
**«Ученики будут открывать и сдавать самостоятельные»** — фатальное. Всё остальное (польза для репетитора, вытеснение CloudText) не случится, если форма не доходит до ученика. Проверка до сборки основного объёма: минимальный срез (см. «Что строить первым») + 2 недели пилота у трёх лидеров + сравнение открытий/сдач с обычными ДЗ. Если открываемость просядет хуже, чем на треть относительно ДЗ, — стоп, разбираться с вовлечением, а не строить Фазу 2. [все риски и out-of-scope ▸](#l3-risk)

# Полная спека

## Section 0: Job Context (обязательная секция спек SokratAI)

- **Core Job (Т-СР):** «Когда тема пройдена, я хочу назначать ученику работу с нужной мне степенью участия AI — от тренировки с подсказками до среза без помощи и полной репетиции экзамена — и видеть по каждой форме честную оценку, чтобы понимать, что ученик умеет САМ, а не с AI». Источник: `docs/discovery/research/11-ajtbd-users-jobs-segments-nmt-2026-07.md` §2.1 (строка бэклога #39, ранг 3).
- **Big Job:** С1 — «разорвать связь "доход = часы" без потери качества»; С2 — «одна платформа и единый стандарт для школы без роста расходов».
- **Место в графе работ:** закрывает Разрыв №2 КПР С1 («решает с нужной степенью AI») и наследуемый разрыв КПР С2; кормит R1-3 (классификация ошибок, Фаза 2) и R3 (отчёт родителю, forward-link).
- **Усиление wedge:** да — расширяет ядро «самостоятельная работа учеников между уроками» и убивает причину держать вторую платформу; не generic-чат; AI-вывод заканчивается действием репетитора (назначить / посмотреть результат / подтвердить).

<a id="l3-challenge"></a>
## 0. Решение о сборке (challenge-гейт)

Лестница цели (5 «почему»): режим «без подсказок» → честная оценка самостоятельности → доверие репетитора к Сократу как инструменту контроля → консолидация на одной платформе (уход CloudText/OnlineTestPad) + рост заходов учеников → удержание/активация пилота (North Star) → MRR.

| Вариант | Что убирает/добавляет | Цена vs оригинал | Рискованное предположение | Победил? |
|---|---|---|---|---|
| Строить режим в ДЗ (как задумано) | Убирает вторую платформу; добавляет флаг+гейты+экран результата | — | Ученики открывают самостоятельные | ✅ (минимальным срезом) |
| Ничего не строить: «пробник = самостоятельная» | Ноль кода | 0 | Репетиторы примут экзамен-обёртку для мини-срезов | — экзамен-обёртка, нет конструктора ДЗ/критериев/занятий; Елена явно просит «назначать как ДЗ»; Эмилия просит «20 мини-тестов» |
| Только «% самостоятельности», без режима | Минимум кода (колонка) | ~10% оригинала | Метрики хватит без среза | — не даёт Job «что умеет сам»: подсказки всё ещё доступны; вошло в скоуп как Т7 |
| Отдельная подсистема «тесты» (третья) | Свобода дизайна | ×3+ | — | — против инварианта «не плодить подсистемы»; хоронит простоту для С2 |

Локальный vs глобальный: это осознанный локальный ход по ядру (расширение работающей системы ДЗ); глобальный трек (канал школ, С2) идёт параллельно ops-мероприятиями без кода. Вычитание применено: из v1 убраны настройка reveal-политики (один дефолт), таймер, дедлайн-запрет, mock-чекеры Ч1, живой real-time монитор.

<a id="l3-overview"></a>
## 1. Обзор

- **Строим:** вид работы `Самостоятельная` внутри системы ДЗ + честные оценки поверх всех видов + (Фаза 2) предметная сводка ошибок. Пробник остаётся отдельной системой; таксономия «Домашка / Самостоятельная / Пробник» объединяется на уровне выбора при назначении.
- **Сегменты:** С1 «экзаменационный предметник-одиночка» (Егор, Елена, Вадим, Ульяна, Милада, Светлана — платящие A/B) и С2 «руководитель мини-школы» (Эмилия; критерий №1 — простота для слабого преподавателя). Критерии успеха и Job — Section 0.
- **Aha-моменты:** репетитор — первый открытый результат самостоятельной («вижу, что умеет сам, за минуту»); ученик — экран «Результат работы» с «X из Y» и разбором на его работе. Сдвиг влево: результат ученику — сразу после сдачи работы (не после ручной проверки); результат репетитору — по мере сдач, в реальном времени.
- Challenge не поменял субъект сборки; поменял объём v1 (минимальный срез).

## 2. Целевые пользователи (по Job, не по демографии)

| Роль | Что делает в фиче | Доминирующие критерии |
|---|---|---|
| Репетитор С1 | Назначает вид работы, читает результаты и % самостоятельности | Точность по критериям; время проверки → 0; видна самостоятельность |
| Преподаватель школы С2 | То же, но «нулевая грамотность» | Не ошибиться; понять без инструкции |
| Руководитель С2 | Стандартизирует виды работ в школе | Единый стандарт; контроль |
| Ученик | Решает без AI, сдаёт, видит «X из Y» + разбор | Понятно, что можно/нельзя; быстрый результат; разбор на моей работе |

B2B-цепочка С2 (руководитель → преподаватель → ученик) новых ролей в продукт не добавляет: руководитель действует из-под своего аккаунта (текущая модель школы Эмилии).

<a id="l3-requirements"></a>
## 3. Функциональные требования

### Цепочка шагов (Критическая цепочка работ режима «Самостоятельная»)

```
Репетитор: собрал работу в конструкторе → выбрал вид «Самостоятельная» → назначил (ученикам/группе/к занятию)
→ Ученик: получил уведомление → открыл → [плашка правил] → решает задачи (без hint/chat; можно пропускать)
→ сдаёт ответы по задачам (одна попытка на задачу; проверка выполняется сразу, результат скрыт)
→ нажал «Сдать работу» (или сдал последнюю задачу → автозавершение)
→ ✨ экран «Результат работы»: X из Y, вердикты, разбор, ответы
→ Репетитор: результаты в деталке ДЗ (по мере сдач) → ✨ «вижу, что умеет сам» → [Фаза 2] сводка ошибок
```

Форма цепочки: линейная; внутри блока решения — задачи в свободном порядке (OR по порядку, AND по совокупности). Разрыв-риски: открытие (наследуемое TOC-горло), застревание без подсказок (новый), утечка вердикта до сдачи (anti-leak).

### Фаза 1 — режим «Самостоятельная» + честные оценки

**Т1. Вид работы на назначении.**
Схема: `homework_tutor_assignments.work_mode TEXT NOT NULL DEFAULT 'homework' CHECK (work_mode IN ('homework','independent'))`. Additive-миграция; все write-paths пишут поле: create/update в homework-api, прямой insert HWDrawer (не задаёт → DB default 'homework'), save-as-template и загрузка шаблона переносят вид работы.
*Приёмка:* существующие ДЗ и все пути создания без изменений поведения; шаблон самостоятельной создаёт самостоятельную.

**Т2. Переключатель в конструкторе.**
Сегмент-контрол «Вид работы: Домашка с Сократом · Самостоятельная» на видном месте L0 (не в свёрнутых параметрах — урок «не видела опцию» из CEFR-инцидента), с одной строкой пояснения («Самостоятельная: без подсказок AI, одна попытка, разбор после сдачи»). Рядом — ссылка «Нужен формат экзамена? → Пробник» (переход в mock-флоу; третий вид таксономии, ссылочно).
*Приёмка:* преподаватель без инструкции понимает разницу (проверка 4/4 на пилоте); вид меняется только до первой сдачи любого ученика (после — заблокирован с пояснением).

**Т3. Серверное отключение AI (anti-tamper).**
При `work_mode='independent'`: запрос подсказки и guided-чат возвращают 403 с русской фразой (контракт ошибок проекта); AI-интро не генерится. Клиентские точки входа (чип подсказки, поле обсуждения, интро) скрыты по флагу из данных assignment.
*Приёмка:* прямой вызов hint/chat API на самостоятельной → 403; в UI входы отсутствуют; обычная домашка не затронута.

**Т4. Одна попытка на задачу, без деградации балла.**
Повторная сдача задачи в самостоятельной → 409 («Ответ уже сдан»); понижающие механики домашки (штрафы за подсказки/неверные попытки) не применяются — балл задачи = результат проверки (полный/частичный AI-балл для развёрнутых, полный для верного краткого).
*Приёмка:* повторный сабмит через API → 409; в UI после сдачи задачи — состояние «Сдано», поле ввода заблокировано; балл без штрафов.

**Т5. Сдача работы и отложенный разбор (state-aware).**
Проверка каждой задачи выполняется сразу при сдаче (репетитор видит результаты live), но ученику до завершения работы не возвращаются вердикты/баллы/фидбэк/AI-сообщения — серверное скрытие в student-эндпоинтах (по образцу state-aware reveal пробников), не клиентское. Завершение: кнопка «Сдать работу» (доступна всегда; при несданных задачах — подтверждение «N задач без ответа — они получат 0») ИЛИ автозавершение при сдаче последней задачи. v1 — один дефолт «разбор после сдачи работы»; настройка «разбор сразу по задаче» (решение владельца: тумблер репетитора) — вторым срезом Фазы 1 (Т9).
*Приёмка:* до завершения student-API не содержит вердиктов/баллов (проверка сырых ответов); после завершения — всё раскрыто; репетитор видит результаты до завершения.

**Т6. Экран ученика «Результат работы» (новый).**
После завершения: итог «X из Y баллов» (агрегат уже считается на бэке), список задач с вердиктами (верно / частично / неверно / без ответа — цветовая семантика проекта), переход в задачу для разбора (фидбэк AI, правильный ответ/решение — если у задачи задано), пересдача недоступна. Для обычной домашки этот же экран включается по завершению работы (итог у ученика — закрытие давнего гэпа «ученик не видит суммарный балл»).
*Приёмка:* ученик после сдачи видит «X из Y» ≤ 3 сек; все задачи кликабельны; на iOS Safari 15 экран работает.

**Т7. «% самостоятельности» в обычных домашках.**
Определение (решение владельца): % задач, закрытых без единой подсказки (hint_count = 0), от закрытых задач. Агрегат в results-эндпоинте + колонка в таблице результатов ДЗ (рядом с «Подсказки»); тултип с формулой (конвенция проекта — формула дублируется в подсказке). В самостоятельных не показывается (тривиально 100%).
*Приёмка:* колонка совпадает с ручным пересчётом по task_states; для старых ДЗ считается ретроспективно (данные уже есть).

**Т8. Бейджи вида работы.**
Списки ДЗ репетитора и ученика, деталка, карточка занятия (материал-ссылка) показывают вид «Самостоятельная» (нейтральный бейдж, не alarm). Уведомление ученику о назначении содержит вид работы.
*Приёмка:* ученик до открытия понимает, что это работа без подсказок.

**Т9 (второй срез Ф1). Настройка момента разбора.**
Тумблер репетитора при назначении: «Разбор: после сдачи работы (дефолт) / сразу по задаче». «Сразу» = вердикт и балл задачи раскрываются после её сдачи (подсказки/чат всё равно выключены, попытка одна).
*Приёмка:* оба режима проходят anti-leak-проверку сырых ответов API.

### Фаза 2 — сводка «Типичные ошибки» (идея Елены)

**Т10. Предметная таксономия ошибок.**
Расширить типизацию ошибок при AI-проверке предметно-осознанными категориями; физика (список Елены): воспроизведение формул · выбор формулы · чертёж · проецирование векторов · алгебраические преобразования/системы · арифметика · словесные формулировки/пояснения; generic-набор для остальных предметов до появления их списков от лидеров направлений. Классификация — тем же вызовом проверки (без второго AI-запроса), пишется в существующий событийный лог проверок.
*Приёмка:* на 20 исторических работах физики Елена согласна с категорией в ≥70% случаев (порог доверия — проверить на пилоте Ф2).

**Т11. Сводка за работу.**
В результатах ДЗ у репетитора: блок «Типичные ошибки» по ученику и по работе (счётчики категорий; повторяющиеся — сверху). Данные — из событийного лога проверок (сейчас write-only; начать читать; заглушки `common_error_types`/`error_type_histogram` в results — заполнить).
*Приёмка:* блок появляется при ≥1 классифицированной ошибке; тутор-only (ученику в v2 — решение позже).

**Т12. Сводка за период на карточке ученика.**
На карточке ученика: «Типичные ошибки за период» (работа / неделя / месяц) + AI-текст-саммари по запросу репетитора (кнопка, 2–3 предложения: тенденции + что подтянуть). PII-free, тутор-only; сырьё для будущего отчёта родителю (#11 бэклога — forward-link, не в скоупе).
*Приёмка:* саммари генерится ≤10 сек, упоминает только категории/счётчики/темы, без цитат работ.

> <sub>**▸ methodology trace.** Т1–Т6: Core Job Т-СР → Big Job «доход≠часы»/«одна платформа»; механика: kill-a-job («вести вторую платформу») + perform-more-jobs-with-one-solution; Aha репетитора — первый результат среза. Т7: механика better-meet-criteria (критерий «видна самостоятельность»); Aha — колонка отвечает на вопрос, который раньше требовал интуиции. ## 6. Метрики успеха

- **Метрика рискованного предположения (главная):** открываемость/сдаваемость самостоятельных vs обычных ДЗ у пилотных репетиторов (цель: не хуже −30%; замер по существующим данным открытий/сдач).
- **Adoption репетиторов:** % активных репетиторов, назначивших ≥1 самостоятельную за 30 дней (цель пилота: ≥50% из А/В-сегмента).
- **Kill-a-job:** Эмилия/Елена подтверждают отказ от CloudText/OnlineTestPad для срезов (качественно, к концу пилота Ф1).
- **Aha-rate ученика:** % завершивших работу, открывших экран «Результат работы» (цель ≥90% — экран показывается сам).
- **Ф2:** % работ с заполненной сводкой ошибок; согласие Елены с категориями ≥70% на выборке.

**Out-of-scope (вычтено осознанно):**
- **Не для кого:** онлайн-школы с прокторингом и античитом (не наш сегмент); подготовка «только пробники» без домашек; кейсы, требующие таймера/запрета после дедлайна (отложено носителем запроса).
- **Отложено в другие фичи:** живой real-time монитор «кто на каком вопросе» (#44); mock-чекеры Ч1 с частичным баллом в ДЗ-задачах (остаётся пробникам); «работа над ошибками: AI-двойник задачи» (#42 — отдельный PRD); отчёт родителю (#11 — потребитель данных Ф2); правка категорий ошибок репетитором (v2 Ф2); показ сводки ошибок ученику (решение позже); таймер и запрет отправки после дедлайна.
- **Анти-требования:** не строить третью подсистему; не менять экзаменационную целостность пробников; вид работы не влияет на квоты AI-сообщений ученика (самостоятельная их не расходует — AI-путей нет).

> <sub>**▸ methodology trace.** RAT: выживание мультипликативно — список сокращён вычитанием (таймер/дедлайн/настройки убраны из v1, чтобы не тащить их риски); MVP = зонд (минимальный срез Т1–Т6 тестирует R1, не «продукт»); фатальный риск получает самую левую проверку.</sub>

## 8. Нефункциональные требования

- **Anti-leak:** скрытие вердиктов — только сервером (student-эндпоинты), паттерн state-aware; клиентское скрытие — вспомогательное. Новые поля ученику — по явному решению (default paranoid — конвенция проекта).
- **Совместимость:** Safari 15 / iOS 15 (базлайн проекта); deploy-skew: старые бандлы получают серверные 403/скрытие корректно (кейс #11).
- **Производительность:** экран «Результат работы» — один запрос (существующие агрегаты); сводка ошибок — чтение событийного лога с индексом по ученику+периоду.
- **Приватность:** сводки ошибок PII-free (категории/счётчики/темы), тутор-only.
