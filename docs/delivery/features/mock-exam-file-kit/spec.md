# Комплект файлов пробника в AI-загрузчике (corrigé + транскрипт + критерии)

**Статус:** спека v0.1 (код после ручной загрузки B1 Junior — решение владельца 03.08.2026).
**Живой кейс-эталон:** DELF B1 Junior Sujet_démo (exemple 2) — собран вручную 03.08, вариант `3934598e-10f7-5110-81c5-c7dddaa97df2`; формат комплекта выучен на нём.

## Section 0: Job Context

Запрос Софии (куратор школы Эмилии, 03.08, дословно): «можно было бы сделать так, чтобы прикрепить в Сократ не только пробник, но и ответы… Потому что у нас есть отдельно пдф файл пробника, отдельно ответы файл. И критерии оценивания также. Было бы супер сразу все файлы загружать в Сократ, чтобы не добавлять вручную ответы на вопросы в аудио».

Job — продолжение J10/J1 (единый пробник, `2026-07-24-cloudtext-emilia-research.md`): у экзаменационных издательств пробник ВСЕГДА приходит комплектом (candidat + correcteur + surveillant + grilles), а наш загрузчик принимает только первый файл — остальное репетитор перебивает руками. Усиливает и не-языков: физика/химия грузят «сборник + ответы» тем же паттерном.

## Комплект (типизация по живому кейсу DELF)

| Файл | Роль | Куда ложится |
|---|---|---|
| candidat (сам пробник) | условия | задачи + блоки (как сейчас) |
| **correcteur / CORRIGÉ** | ответы И веса каждого вопроса | `correct_answer` + `max_score` |
| **surveillant / транскрипт** | текст аудио по exercice | `block_transcripts_json` соответствующих блоков |
| **grille (критерии)** | матрица оценивания Части 2 | `solution_text`/`solution_image_urls` задач Части 2 (v1) |
| mp3-треки | аудио блоков | кураторы прикрепляют в редакторе (own-namespace, автоматизации нет) |

## Решения

1. **Файл ответов → расширение `answers_table` (W4), не новый механизм.** Уже есть кросс-чанковый мердж по `source_num`. Дорабатываем:
   - **Секционность:** нумерация DELF рестартует в каждом exercice → ключ мерджа `(section, num)`, где `section` модель извлекает из заголовков («EXERCICE 1», «Часть 1»). Физике/химии секция пустая — прежний мердж байт-в-байт.
   - **Веса из барема:** `answers_table` получает опц. `points` («1,5 point» рядом с ответом) → сид `max_score` (приоритет над картой ФИПИ только при явном барème; телеметрия).
   - **Промпт-правило «страницы CORRIGÉ/БАРЕМ/ОТВЕТЫ — только answers_table, задачи из них НЕ создавать»** — иначе загрузчик плодит задачи из строк ответов (сейчас corrigé-PDF в общем прогоне сделал бы именно это).
2. **Файл транскрипта:** детект секций «EXERCICE N / TRANSCRIPTION» → текст в транскрипт блока N (мэппинг по порядку блоков с аудио; UI ревью показывает «транскрипт → блок» с возможностью перекинуть). Нет блоков → в variant-level `listening_transcript`.
3. **Grille:** v1 — страницы grille прикрепляются фото к задачам Части 2 (`solution_image_urls`) + текстовая выжимка в `solution_text`. Структурная интеграция в AI-грейдер (критерии → `grading_criteria_json`-аналог для пробников) — отдельная спека, у `mock_exam_variant_tasks` колонки критериев нет.
4. **UI:** в `InputStage` (destination `mock_variant`) — три отдельные кнопки «Файл ответов», «Транскрипт», «Критерии» рядом с основной загрузкой; файлы прогоняются тем же чанкингом, но с ролью в промпте. Роль по кнопке, НЕ автодетект имени файла (у Дианы/Ульяны имена произвольные).

## Критерии приёмки

- **AC-1.** Прогон «candidat + correcteur» DELF: ≥90 % задач получают ответ и вес из corrigé без ручного ввода; ни одной задачи, созданной из страниц corrigé.
- **AC-2.** Секционный мердж: две задачи с одинаковым `source_num` в разных exercices получают КАЖДАЯ свой ответ.
- **AC-3.** Транскрипт-файл: блоки с аудио получают свои транскрипты; UI показывает мэппинг до commit.
- **AC-4.** Нерегрессия: прогон физического «сборник + ответы» (эталон W4) — мердж и counts байт-в-байт (пустая секция).
- **AC-5.** Веса: явный барème побеждает карту ФИПИ; без барème — прежний порядок (карта → AI).
