Проблема оказалась шире одного экрана: **канонического просмотрщика фото в

## Решения владельца

| Вопрос | Решение |
|---|---|
| Где живёт разметка | **Оба пути**: быстрый слой во вьюере + «Разобрать на доске» |
| Что получает ученик | **Плоский PNG с пометками** сообщением в тред ДЗ |
| Охват v1 | **Единый вьюер во всех местах** + разметка только в проверке ДЗ |
| Хранение поворота | **Гибрид**: таблица углов + запекание в пиксели при рендере PNG |
| Инструменты разметки | Перо + ластик + отмена, маркер, стрелка + рамка/овал, текст |
| Устройство | **Оба равнозначно** — touch-first + горячие клавиши |
| Выкатка | **Две волны** |
| Метрики | Adoption разметки + «ученик исправил ошибку» |

### Почему угол в таблице, а не перезаписью файла

Не из-за объёма данных, а из-за скорости и обратимости:

| | Таблица углов | Перезапись файла |
|---|---|---|
| Отклик | мгновенно (transform), запись фоном | 1,5–7 с: скачать → decode → canvas → encode → upload → сброс кэша; на iPad ещё и фриз (`OffscreenCanvas` в iOS 15 нет) |
| Качество | пиксели нетронуты | каждый поворот = новое JPEG-сжатие (химия с индексами — худший случай) |
| Обратимость | крутнул назад бесплатно | **необратимая перезапись работы ученика** |
| Права | аддитивная таблица | новый write-path в storage ×4 бакета |

Единственный плюс перезаписи — AI и скачанный файл «из коробки» — закрывается
строкой в промпте грейдинга.

## Волна 1 — реализовано

### Модель хранения

`photo_orientations(ref PK, degrees, updated_by, updated_at)`, миграция
`20260731120000_photo_orientations.sql`. Одна сущность на все домены — ДЗ,
пробники, чат, Банк, материалы: колонка в каждой схеме означала бы шесть
миграций и новые write-site там, где уже есть двойной write-path (rule 40).

⚠️ **Anti-leak:** `ref` — это путь в storage, поэтому **список ref'ов не
отдаётся никому**. Прямых GRANT'ов на таблицу у `anon`/`authenticated` нет;
доступ только через SECURITY DEFINER:

- `photo_orientations_get(text[])` — возвращает строки лишь для УЖЕ ИЗВЕСТНЫХ
  вызывающему ref'ов, кап пачки 200. Доступна и ученику: смысл фичи в том, что
  повёрнутое репетитором фото ученик видит так же.
- `photo_orientations_set(text, int)` — гейт `is_tutor(auth.uid())`,
  нормализация угла на сервере (зеркало клиентской).

Тройной REVOKE в правильном порядке (GRANT → REVOKE PUBLIC → REVOKE anon,
rule 99) + явный `GRANT ALL ... TO service_role` (default privileges схемы для
новых таблиц его не покрывают — урок миграций доски).

### Ключевые инварианты

1. **При увеличении один палец панорамирует, свайп между фото отключается.**
   Конфликт этих жестов — самая частая поломка лайтбоксов.
2. **Положение живёт в ref, transform пишется в rAF.** React-состояние меняется
   только на пересечении порога «увеличено/вписано» — приём `BoardCanvas`.
3. **Натуральные размеры дочитываются у готового элемента, а не только по
   `onLoad`.** Для уже декодированной картинки (кэш браузера, прогрев соседей —
   а просмотрщик их прогревает сам) `load` успевает выстрелить ДО того, как
   React повесит обработчик. Симптом пропуска: фото вылезает за сцену
   (поймано браузерной проверкой 31.07: 779 px в контейнере 570 px).
4. **Поворот наследуется миниатюрой** — иначе репетитор решит, что он не
   сохранился, и будет крутить каждый раз заново.
5. **Ref восстанавливается из подписанной ссылки** (`storageRefFromUrl`) там,
   где бэкенд отдаёт только URL (пробники, материалы) — без прокидывания
   второго поля через edge. Чужая ссылка → `null`, поворот локальный.
6. **Габариты кадра после поворота меняются местами** — вписывание считается по
   повёрнутым размерам, иначе альбомный лист в портрете вылезает за экран.

## Волна 2 — реализовано

### Маркер и стрелка в общей модели доски

`StrokeElement.opacity` и `ShapeKind='arrow'` — **аддитивно**: сцены, записанные
до их появления, читаются без миграции. Доска получает оба инструмента тем же
коммитом и закрывает **B5** и **B6** своего P1-бэклога.

- **Маркер рисуется `fill-opacity`, а НЕ `opacity` узла.** Последний применился
  бы к узлу целиком, и наложение двух маркерных штрихов давало бы тёмный шов на
  пересечении — подсветка выглядела бы грязной ровно там, где ей пользуются.
- **Стрелка — один `<path>` с ОБВОДОЧНЫМ наконечником.** Залитый треугольник при
  толстом пере превращается в кляксу; обводка наследует толщину древка. Ус
  ограничен третью длины — иначе короткая стрелка состоит из одного наконечника.
- **Ластик для линии и стрелки меряет расстояние до отрезка, а не до bbox.**
  У диагонали прямоугольник почти весь пустой, и ластик стирал бы её, «зацепив»
  воздух рядом (та же причина, по которой штрих меряется по ломаной).

### Координаты разметки — пиксели НЕповёрнутого фото

Пометка привязана к самому снимку, а не к тому, как он сейчас показан. Поворот
уже ПОСЛЕ разметки не сдвигает обводку — иначе это была бы неисправимая для
пользователя ошибка, он бы решил, что фича сломана. Тот же выбор делает экспорт
корректным бесплатно: фото и разметка кладутся на канву одним преобразованием.

Обратный поворот считается **целочисленной перестановкой**, а не через sin/cos:
тригонометрия дала бы 6.1e-17 вместо нуля и координаты накапливали бы дрейф.

Толщина пера и кегль текста считаются **от диагонали снимка**: на фото 4000 px
линия в 3 px — волосок, на скриншоте 600 px — клякса.

### Холст

`AnnotateCanvas` — **не форк** 1500-строчного `BoardCanvas`. Переиспользованы
только чистые части: `perfect-freehand` через `svg.ts`, модель элементов,
`SceneHistory`. Инварианты ввода повторены сознательно — они куплены багами
доски: живой штрих в ref + rAF, нажим только для `pointerType === 'pen'`, пинч
требует обоих `touch` (ладонь не превращает рисование в масштаб), ластик
коммитит жест одним шагом отмены, `preventDefault` на pointerdown (иначе
действие по умолчанию крадёт фокус у поля текста).

⚠️ `setPointerCapture` обёрнут в try: на неактивном `pointerId` браузер бросает
`NotFoundError`, и необработанное исключение обрывало обработчик до старта
жеста — рисование молча переставало работать (поймано браузерной проверкой).

### Сборка JPEG

Два прохода по канве, а не один SVG: документ, загруженный как `<img>`, **не
подтягивает внешние ресурсы**, поэтому `<image href>` внутри него не
отрисовался бы. Фото рисуется `drawImage`, разметка — самостоятельным SVG
поверх. Анти-taint через blob-URL (иначе `toBlob` бросает SecurityError).

**Поворот запекается в пиксели ровно здесь** — в остальном продукте он живёт
углом в `photo_orientations`, а файл ученика остаётся нетронутым.

⚠️ Текст разметки в растре рисуется общесистемным шрифтом: у SVG-как-картинки
нет доступа к шрифтам документа. Подписи короткие — осознанный размен.

### Отправка и черновик

⚠️ **Своего write-path у разметки нет.** Лист собирает JPEG и отдаёт наружу;
отправляет владелец треда существующей парой
`uploadTutorHomeworkTaskImage` → `postTutorThreadMessage` + оптимистичный merge
в кэш (rule 40).

Черновик держится в `sessionStorage` по storage-ref — прямой ответ на страх
Ульяны U17: «столько времени переводить все домашки, и если вдруг будет
зависать — это прямо катастрофа».

### «Разобрать на доске»

Второй путь из решения владельца: когда поверх фото места не хватает и решение
надо расписать рядом. Создаётся **отдельная** доска «Разбор ДЗ · <ученик>» —
тред ДЗ не знает про занятие, и заставлять выбирать урок посреди проверки было
бы лишним шагом. Поворот запекается в файл перед загрузкой: положить его в
`ImageElement.rotation` нельзя — рамка элемента остаётся неповёрнутой, и портрет
на 90° вылез бы за края листа.

## Фикс-пасс по ревью качества (UX / перфоманс / архитектура)

Вердикт ревью: **условный go**, 7/10 · 7/10 · 8/10 — концепцию и границы
модулей менять не надо. Закрыты все три пункта «до пилота» плюс оба «дёшево
сейчас, дорого через два месяца».

| Что | Почему это было важно |
|---|---|
| `crypto.randomUUID` → Safari-safe генератор в `uploadTutorHomeworkTaskImage` | На iOS 15.0–15.3 это TypeError, и отправка падала ДО сети. Код старый, но разметка от него зависит целиком (rule 80) |
| HEIC декодируется и на экспорте | Во вьюере его показывает `SafeImage`, поэтому репетитор ВИДИТ фото и размечает — а терял работу на последнем шаге |
| Закрытие СОХРАНЯЕТ черновик, выбрасывает только «Отмена» с подтверждением | Раньше и крестик, и «Отмена» вели в `discard`: обещание «труд не потеряется» (U17) не выполнялось нигде, кроме падения вкладки. Плюс гард гидратации — эффект сохранения видел ещё пустой `elements` |
| Политика Pencil / палец / ладонь | Карта указателей хранила только координаты, любые два указателя = пинч. Ладонь рядом со стилусом отменяла штрих — а это главный пилотный сценарий. ⚠️ Инвариант был описан в шапке файла, но не реализован |
| `getCoalescedEvents` для пера | Сэмплы между кадрами терялись, длинные дуги выходили угловатыми |
| `message_kind='photo_annotation'` + CHECK-миграция | Без долговечного признака метрика №2 считалась бы по НЕОБЯЗАТЕЛЬНОЙ русской строке подписи. ⚠️ Миграция обязательна вместе с кодом — иначе вставка падает 23514 |
| Запись поворота выстроена в цепочку по ref | `seq` защищал кэш, но не сервер: «180°» мог доехать раньше старого «90°», и после перезагрузки остался бы 90° |
| `photo_orientations_set` ограничен бакетами работ | Раньше любой репетитор, знающий ref, разворачивал любое изображение, включая общий каталог Банка. Каталог в allowlist НЕ входит намеренно |
| В подвале вьюера одна CTA | «Разобрать на доске» конкурировала с основной и не переносилась на узком экране; путь переехал в лист как «Нужно больше места» |
| Необязательное поле «Что исправить?» | Пометка отвечает на «где», подпись — на «что». Вторая половина и работает на метрику «ученик исправил ошибку» |

**Осознанно отложено:** idempotency key для повторной отправки — требует
миграции с уникальным индексом, а режим отказа это видимый дубль сообщения, а
не порча данных; авторетраев у мутаций нет (rule 60 #10).

**Не сделано:** замеры на реальном iPad — без устройства невозможны. План
замеров: input-to-next-paint и доля кадров >16,7 мс вместо INP (он плохо
описывает непрерывное рисование), peak memory на входном фото 8000×6000,
время «Отправить» → сообщение в треде.

## Метрики

**Primary:** adoption разметки (доля проверок с фото, где отправлена размеченная
картинка; репетиторы с ≥3 применениями за неделю) и «ученик исправил ошибку»
(новый ответ + рост балла после сообщения с разметкой; **baseline замерить ДО
выката**).

**Guardrail:** p75 открытия фото ≤ 400 мс · доля `client_error` на страницах
проверки не растёт · доля фото, открытых сырой вкладкой браузера → 0.

**События:** `photo_viewer_opened{surface,count}` · `photo_rotated{surface,degrees,persisted}` ·
`photo_annotate_started` · `photo_annotate_sent{strokes,tools,duration_ms}` ·
`photo_annotate_discarded` · `photo_to_board`.
