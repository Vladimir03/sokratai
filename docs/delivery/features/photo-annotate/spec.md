## Что показала разведка кода

Проблема оказалась шире одного экрана: **канонического просмотрщика фото в
кабинете не было вообще**.

- 4 независимые копии одной карусели (`homework/shared/PhotoGallery`,
  `FullscreenImageCarousel`, `student/.../TaskImagesGallery`, локальная копия в
  `AdminHWThreadView`);
- 6+ мест, где «увеличить» = открыть сырую вкладку браузера (тред ДЗ, пробники ×5,
  Банк знаний ×3);
- ни одна не умела ни зум, ни панораму, ни поворот;
- HEIC-восстановление (баг Ирины Бочаровой, 2026-07-30) работало на **2**
  поверхностях из ~15.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Где живёт разметка | **Оба пути**: быстрый слой во вьюере + «Разобрать на доске» |
| Что получает ученик | **Плоский PNG с пометками** сообщением в тред ДЗ |
| Охват v1 | **Единый вьюер во всех местах** + разметка только в проверке ДЗ |
| Хранение поворота | **Гибрид**: таблица углов + запекание в пиксели при рендере PNG |
| Инструменты разметки | Перо + ластик + отмена, маркер, стрелка + рамка/овал, текст |
| Устройство | **Оба равнозначно** — touch-first + горячие клавиши |
| Выкатка | **Две волны** |
| Метрики | Adoption разметки + «ученик исправил ошибку» |

### Почему угол в таблице, а не перезаписью файла

Не из-за объёма данных, а из-за скорости и обратимости:

| | Таблица углов | Перезапись файла |
|---|---|---|
| Отклик | мгновенно (transform), запись фоном | 1,5–7 с: скачать → decode → canvas → encode → upload → сброс кэша; на iPad ещё и фриз (`OffscreenCanvas` в iOS 15 нет) |
| Качество | пиксели нетронуты | каждый поворот = новое JPEG-сжатие (химия с индексами — худший случай) |
| Обратимость | крутнул назад бесплатно | **необратимая перезапись работы ученика** |
| Права | аддитивная таблица | новый write-path в storage ×4 бакета |

Единственный плюс перезаписи — AI и скачанный файл «из коробки» — закрывается
строкой в промпте грейдинга.

## Волна 1 — реализовано

### Модель хранения

`photo_orientations(ref PK, degrees, updated_by, updated_at)`, миграция
`20260731120000_photo_orientations.sql`. Одна сущность на все домены — ДЗ,
пробники, чат, Банк, материалы: колонка в каждой схеме означала бы шесть
миграций и новые write-site там, где уже есть двойной write-path (rule 40).

⚠️ **Anti-leak:** `ref` — это путь в storage, поэтому **список ref'ов не
отдаётся никому**. Прямых GRANT'ов на таблицу у `anon`/`authenticated` нет;
доступ только через SECURITY DEFINER:

- `photo_orientations_get(text[])` — возвращает строки лишь для УЖЕ ИЗВЕСТНЫХ
  вызывающему ref'ов, кап пачки 200. Доступна и ученику: смысл фичи в том, что
  повёрнутое репетитором фото ученик видит так же.
- `photo_orientations_set(text, int)` — гейт `is_tutor(auth.uid())`,
  нормализация угла на сервере (зеркало клиентской).

Тройной REVOKE в правильном порядке (GRANT → REVOKE PUBLIC → REVOKE anon,
rule 99) + явный `GRANT ALL ... TO service_role` (default privileges схемы для
новых таблиц его не покрывают — урок миграций доски).

### Ключевые инварианты

1. **При увеличении один палец панорамирует, свайп между фото отключается.**
   Конфликт этих жестов — самая частая поломка лайтбоксов.
2. **Положение живёт в ref, transform пишется в rAF.** React-состояние меняется
   только на пересечении порога «увеличено/вписано» — приём `BoardCanvas`.
3. **Натуральные размеры дочитываются у готового элемента, а не только по
   `onLoad`.** Для уже декодированной картинки (кэш браузера, прогрев соседей —
   а просмотрщик их прогревает сам) `load` успевает выстрелить ДО того, как
   React повесит обработчик. Симптом пропуска: фото вылезает за сцену
   (поймано браузерной проверкой 31.07: 779 px в контейнере 570 px).
4. **Поворот наследуется миниатюрой** — иначе репетитор решит, что он не
   сохранился, и будет крутить каждый раз заново.
5. **Ref восстанавливается из подписанной ссылки** (`storageRefFromUrl`) там,
   где бэкенд отдаёт только URL (пробники, материалы) — без прокидывания
   второго поля через edge. Чужая ссылка → `null`, поворот локальный.
6. **Габариты кадра после поворота меняются местами** — вписывание считается по
   повёрнутым размерам, иначе альбомный лист в портрете вылезает за экран.

### Переведённые поверхности

Тред ДЗ (`ThreadAttachments`) · условие/критерии/эталон
(`PhotoGallery` → `TutorHomeworkDetail`, `GuidedThreadViewer`,
`HomeworkPreviewContent`) · пробники (`TutorMockExamReview` — бланк Части 1,
доп. фото, решение ученика, эталон, bulk-пачка; `Part1TaskDrillDownDialog`;
`MockExamVariantPreviewSheet`) · Банк знаний (`kb/TaskCard` ×3 галереи) · чат
(`ChatImageAttachments`) · конструктор и загрузчики (`FullscreenImageCarousel`).

`PhotoGallery` и `FullscreenImageCarousel` стали тонкими обёртками над
`PhotoViewer` — контракт props сохранён, поэтому существующие вызовы не правились.

В `KBPickerSheet` и `HWDrawer` просмотрщик намеренно НЕ вешали: строка там —
это выбор задачи, клик по фото конфликтовал бы с основным действием. Сырой
`<img>` заменён на `SafeImage` (HEIC + фолбэк, rule 40).

## Волна 2 — впереди

Разметка (перо, маркер, стрелка, рамка, текст, ластик) поверх фото в проверке
ДЗ; растеризация SVG → PNG с запеканием поворота; отправка сообщением в тред
через СУЩЕСТВУЮЩИЙ write-path; черновик в `sessionStorage`; «Разобрать на доске».

Маркер (`StrokeElement.opacity`) и стрелка (`ShapeKind='arrow'`) добавляются в
общую модель доски — она закрывает ими **B5 и B6** из своего P1-бэклога.

## Метрики

**Primary:** adoption разметки (доля проверок с фото, где отправлена размеченная
картинка; репетиторы с ≥3 применениями за неделю) и «ученик исправил ошибку»
(новый ответ + рост балла после сообщения с разметкой; **baseline замерить ДО
выката**).

**Guardrail:** p75 открытия фото ≤ 400 мс · доля `client_error` на страницах
проверки не растёт · доля фото, открытых сырой вкладкой браузера → 0.

**События:** `photo_viewer_opened{surface,count}` · `photo_rotated{surface,degrees,persisted}` ·
`photo_annotate_started` · `photo_annotate_sent{strokes,tools,duration_ms}` ·
`photo_annotate_discarded` · `photo_to_board`.
