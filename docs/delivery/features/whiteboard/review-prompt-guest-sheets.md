## Контекст: что чинили

Живые тесты 30–31.07 провалились дважды: (1) гость не из CRM-списка НЕ МОГ получить право писать никогда (Елена: «тестирование провалено», ученик Ульяны «не смог написать»); (2) пикер «Раздать зоны» показывал безымянные CRM-строки «Ученик ×4» (claim-invite/telegram-bot создавали `tutor_students` без `display_name`); (3) перезаход гостя плодил дубли «Владимир, Владимир». Решение — инверсия потока: лист выдаётся ПРИШЕДШЕМУ автоматически при входе, а не строке из CRM заранее.

## Приёмочные сценарии (проверять КАЖДЫЙ по коду, таблицей ЗАКРЫТ/ЧАСТИЧНО/НЕТ)

1. Гость вошёл по ссылке со СВОБОДНЫМ именем (нет в CRM) → его лист создан автоматически в свободном столбце, он пишет ≤30 с, репетитор ничего не делал.
2. Гость выбрал «я — Маша» из списка → авто-лист привязан к `tutor_students` (идемпотентно: если зона Маши уже есть — вторая не создаётся).
3. Перезаход той же личности (или «Сменить имя» → то же имя) → прежний гость ревокнут, его листы ПЕРЕПРИВЯЗАНЫ новому входу, человек продолжает на своём листе, в панели «На доске» — одна запись.
4. «Ученик ×N» исчез: claim-invite и telegram-bot копируют имя из `profiles.username` при создании связки; бэкфил в миграции закрыл старые.
5. Репетитор может отдать/забрать ЛЮБОЙ лист через селект «чей лист» — включая гостей («Имя — по ссылке», офлайн помечен); привязки взаимоисключимы (CHECK).
6. «Раздать зоны» больше не в шапке — вторичная ссылка «Подготовить листы заранее» в диалоге «Пригласить».
7. Камера вошедшего встаёт на ЕГО лист + разовая подсказка; «+ Лист» растит рулон гостя вниз (кап 20).

## Что проверять сверх приёмки (по приоритету)

1. **Безопасность bearer-модели.** ПРИНЯТО ВЛАДЕЛЬЦЕМ (не флагать как P0): любой со ссылкой может назваться чужим именем — теперь это ещё и перепривязывает листы тёзки (то же для «я — Маша» из CRM). Это осознанная Zoom-модель; ссылка отзывается. Флагай только НОВЫЕ векторы сверх неё: может ли гость получить/перепривязать лист ЧУЖОЙ доски или другой ссылки (rebind фильтрует по `share_link_id`?); утечки в ответах (guest_token, tutor-only поля); `zone_guest_id` patch/create в whiteboard-api — точно ли проверяется принадлежность гостя ЭТОЙ доске; GRANT SELECT — не открывает ли лишнего.
2. **Гонки join.** Insert → rebind → revoke → ensure-sheet неатомарны: одновременный двойной вход той же личности, вход во время «Сменить имя», rebind во время автосейва старым токеном (401 после ревока — клиент уводится на join-экран корректно?). CHECK-конфликты: перепривязка листа, у которого вдруг есть `zone_tutor_student_id` (возможно ли?).
3. **Целостность синка.** Ревок+rebind бампят rev перепривязанных листов; авто-лист виден репетитору через realtime (bump в `createRollSheet`); writable у гостя после rebind (myGuestId нового входа против zone_guest_id листов); LWW/CAS не задеты.
4. **Правка telegram-bot** — рядом ли инвариант «бот всегда отвечает» (rule 60), не сломан ли flow привязки при NULL username.
5. **Перфоманс.** guestNames/onlineGuests в memo-цепочках; поллинг гостей не дёргает лишних ре-рендеров; join-путь — один edge-вызов.
6. **Cross-browser (rule 80)**: baseline Safari 15/iOS 15, 16px, touch-action; **контракты**: rule 97 (non-2xx JSON RU), rule 96 (никакого `*.supabase.co` в клиенте), rule 60 (FK-дрейф), идемпотентность миграции (Lovable кладёт дубль-копии).
