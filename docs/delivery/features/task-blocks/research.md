## 0. Расхождения с постановкой задачи (находки)

1. **Блоки в проде не использует никто.** Миграции применены (колонки, CAS, гранты живые), но `task_blocks_json` пуст у всех вариантов и ни одна задача не несёт `block_id`. «DELF B1 junior» Эмилии — до сих пор плоский список: преамбула «Vous souhaitez faire un stage…» продублирована в **7** задачах (не 6), «APPRENDRE L'HISTOIRE AUTREMENT» — в **3**; аудио она тоже не загрузила (`listening_audio_url IS NULL`). Её окно оформления пробников — 1–5 число, то есть прямо сейчас. Adoption-сигнал важнее новых доменов: если за это окно блоки не появятся — проблема в редакторе, а не в охвате.
2. **У Милады в проде НЕТ заданий 17–20.** Все её варианты обществознания — Часть 1 (задания 1–16); из «Части 2» есть одна строка-заглушка «Тип 25 № 75152» (14 символов). Реплика «блоки 17–20 заведены в проде» — про структуру ЕГЭ, не про её данные. Блоки ей нужны *на будущее* Части 2, гейт её пока ни от чего живого не отрезает.
3. **Масштаб дублирования в Банке при честном подсчёте скромный.** 1272 задачи с полностью идентичным текстом (626 кластеров) — это кросс-аккаунтные дубли импорта Дианы (433 структурных теста у неё + 433 зеркальных у аккаунта «Владимир_реп»), не блоки. Настоящий блок-паттерн «один материал + разные вопросы» внутри одного владельца: **~38 кластеров / ~90 задач**. Лидер — Ульяна (химия): 7 кластеров / 25 задач, включая живой блок «полудрагоценные камни» (общий список минералов + 6–8 вопросов «определите степени окисления в …»). Диана — 10/20 (тексты с пропусками, один текст → вопросы про разные буквы). Математические кластеры («Водитель автомобиля начал торможение…» и т.п.) — с виду шаблонные вариации одной задачи с разными числами, а не общий материал: в оценку block-benefit их включать нельзя без ручной проверки.
4. **Физика ОГЭ: «текст физического содержания» с 2025 сокращён до ОДНОГО задания (№ 18)** — группа из одного вопроса, т.е. у Егора-физика блоки в ОГЭ фактически отпали, в ЕГЭ их и не было. Егоров интерес — про русский/химию его коллег, не про его собственный предмет.
5. **Русский ЕГЭ: текстовый блок — задания 23–26 (+27), а не 22–26.** С 2025 задание 22 (новое) НЕ опирается на макротекст.

## 2. Архитектурные развилки — решения

### 2.1 Где живёт блок → per-domain контейнер, единый shape, снимковый перенос

**Выбор:** блок остаётся доменной сущностью в каждом из трёх доменов, но с ОДНИМ и тем же shape (`{id, title, instruction, image_url, audio_url}` + транскрипт отдельно). Источник переиспользуемого контента — Банк (`kb_blocks`, новая таблица); пробник и ДЗ получают СНИМОК блока при переносе (как задачи: `kb_task_id` → снимок). Провенанс — `source_kb_block_id` в элементе снимка.

**Отвергнуто: одна общая таблица blocks с FK из трёх доменов.** Причины: (а) вся платформа снимковая — правка источника не должна мутировать выданные работы (unified-task-model, LOCKED-решения владельца); (б) reveal-политики транскрипта ПРОТИВОПОЛОЖНЫ по доменам (ДЗ tutor-only навсегда, пробник post-submit) — одна строка не может нести обе; (в) RLS/grants у доменов свои; (г) пробничная реализация прошла внешнее ревью и живёт — переделка без пользы.

**Чем платим:** материал существует в ≤3 копиях (Банк + вариант + ДЗ); правка источника не чинит уже выданное — но это норма платформы, репетиторы её знают по задачам.

### 2.2 Форма хранения → JSONB для снимков, таблица для Банка

- **Пробник, ДЗ (снимки):** JSONB на родителе — как сейчас. Кап 10, валидатор, CAS `content_revision`, атомарные RPC — всё уже есть в пробниках; в ДЗ зеркалим (`homework_tutor_assignments.task_blocks_json` + `block_transcripts_json` + `homework_tutor_tasks.block_id text`). **Миграцию пробников JSONB→таблица НЕ делать**: живых данных ноль, выгоды ноль.
- **Банк (источник):** отдельная таблица `kb_blocks (id, owner_id, title, instruction, image_url, audio_url, transcript, created_at, updated_at)` + `kb_tasks.block_id uuid NULL REFERENCES kb_blocks(id) ON DELETE SET NULL`. Что даёт FK: правка материала в одном месте для N задач; целостность привязок; транскрипт — колонка, до которой у учеников нет пути (весь Банк tutor/moderator-only с M2b); публикация source→copy по образцу задач; в Банке блоку не на чем висеть JSONB'ом — у задач нет общего родителя, кроме папки, а перенос задач между папками порвал бы блок.
- Чем платим: +1 таблица, RLS, батч-подгрузка блоков на поверхностях Банка (`.in(block_ids)` по видимым задачам, дедуп), правка `types.ts`.
- Аудио блока Банка хранить в бакете `mock-exam-listening-audio/{ownerUserId}/…` — переиспользуем бакет и own-namespace валидатор вариантов, тогда «свой блок → свой вариант» работает БЕЗ blob-copy. Помнить: лимиты бакета на Lovable Cloud выставить нечем, клиентская валидация — единственная линия (инвариант rule 45).

### 2.3 Перенос между доменами — где материал теряется сегодня и что чинить

| Путь | Сегодня | Решение |
|---|---|---|
| «+ из БЗ» (path A: `kbTaskToDraftTask` → edge) | блока нет → потеря | `DraftTask` несёт снимок блока; конструктор группирует по `source_kb_block_id`, собирает `task_blocks_json` в create/update body. Пикер предлагает «Добавить весь блок (N)» |
| «В ДЗ» с карточки (path B: `hwDraftStore` → `HWDrawer` прямой INSERT) | блока нет → потеря | v1: **инлайн-фолбэк** — материал приклеивается в начало `task_text` с префиксом «Материал:» + toast «полные блоки — через конструктор». Degrade-not-block; тихой потери нет; AI материал видит (он в тексте). Полноценный довоз — Этап 3 |
| push-to-kb / авто-зеркало (`kb_snapshot.ts`) | блока в ДЗ нет | после Этапа 2: конвертер создаёт/находит `kb_blocks` и линкует. Блок-поля — только presence-семантикой (урок ревью 5.6: безусловный write затирает) |
| Шаблоны (ссылочные) | junction на `kb_tasks` | материал НЕ хранится в шаблоне — восстанавливается по `kb_tasks.block_id` при выдаче. Legacy `tasks_json`-шаблоны блоков не получат (честное ограничение) |
| `copyTaskToFolder` | lossless-копия | копия сохраняет `block_id` (тот же владелец, та же таблица) — бесплатно |
| Банк → вариант (корзина/prefill/AI-загрузчик `mock_variant`) | нет | снимок блока в `task_blocks_json`; своё аудио — ref без копии (общий бакет), **каталожное аудио отбрасывается с предупреждением** (зеркало `dropped_audio_count` при duplicate; blob-copy = известный отложенный долг) |
| Вариант → Банк | пути нет вообще | не строим в v1; долг, назвать в UI нечего — пути «выгрузить вариант в Банк» не существует и для задач |

### 2.4 Одиночная задача из блока → материал едет снимком «блока на один вопрос»

В ДЗ/варианте создаётся блок с одной привязанной задачей. НЕ инлайнить в условие (кроме path B-фолбэка): (а) AI-пути должны отличать материал от условия; (б) инлайн размножает текст и рвёт провенанс; (в) ученик видит материал единообразно. Плата: ДЗ из 5 задач разных блоков = 5 «блоков на один вопрос» — визуально это просто «материал над условием», нормально.

### 2.5 Anti-leak транскрипта по доменам

| Домен | Хранение | Кто видит | Механика |
|---|---|---|---|
| Пробник | `block_transcripts_json`, НЕ гранится | ученик post-submit | как есть (rule 45), не трогаем |
| Банк | `kb_blocks.transcript` колонка | только tutor/moderator | учеников в Банке нет вовсе (M2b: SELECT сужен до tutors/moderators; новые RPC — тройной REVOKE). В каталожную копию блока транскрипт КОПИРУЕТСЯ (потребители — репетиторы) |
| ДЗ | `homework_tutor_assignments.block_transcripts_json` | **tutor-only навсегда** (модель ДЗ = solution_text, rule 40) | не гранится, не селектится student-endpoint'ами; в AI-грейдинг server-side + leak-детектор по токенам (транскрипт длинный — detectLeak работает, в отличие от single_choice-кейса) |

⚠️ Перед добавлением tutor-only колонки на `homework_tutor_assignments` проверить её грант-модель: у tasks/task_states column-GRANT есть (`20260630170000`/`20260516120100`), делался ли REVOKE+whitelist на самих assignments — я в этой сессии НЕ проверял. Если у authenticated table-level SELECT — обязательна GRANT-миграция по образцу `20260801100100`. Это пункт чек-листа реализации, не открытый вопрос дизайна.

Направление переноса безопасно по построению: Банк→ДЗ ужесточает политику (post-submit-класс → tutor-only), Банк→пробник ослабляет осознанно (reveal = ценность продукта).

### 2.6 AI-загрузчик

- **Схема ответа модели (аддитивно):** `blocks: [{key, title, instruction}]` + `drafts[].block_key` (nullable). Edge нормализует fail-open: битый блок → задачи остаются без `block_key`, extraction не падает. Старый клиент поле игнорирует (deploy-skew safe).
- **Промпты:** правка всех 3 зеркал (physics/social/generic) + `prompts.md` §2 ПЕРВЫМ (verbatim-инвариант W2): «Если несколько заданий опираются на один текст/перечень/рисунок — вынеси его в blocks[], в задаче оставь только вопрос; материал НЕ повторяй в task_text».
- **Ограничение чанкинга (главный риск):** чанки по 2 страницы (`CHUNK_IMAGES=2`, W4 — не возвращать к 10). Блок «текст на стр. 1 + вопросы на стр. 3» не соберётся автоматически; «— ПРОДОЛЖЕНИЕ —» помогает частично. v1: распознаём блоки в пределах чанка, cross-chunk merge не обещаем; в ревью — ручное объединение. Замер: доля блоков, собранных без ручного вмешательства, на реальном DELF-PDF Эмилии.
- **UI ревью:** `blockKey` в `ReviewOverrides` (параллельный массив, мягкое скрытие/индексы — инвариант removed[]); в `DraftTable` — строка-заголовок блока (rowheader, редактируемая инструкция) + группировка строк; bulk-действия «Объединить выбранные в блок» / «Открепить от блока». Материал живёт в одном месте, не дублируется в drafts.
- **Мапперы по destination:** `kb_folder` → INSERT `kb_blocks` + `block_id` (в том же bulk-commit цикле, блок первым); `hw_draft`/`mock_variant` → снимок блока в payload конструктора.

### 2.7 Предметный гейт → компактная строка для всех, развёрнутость по предикату

Ресёрч показал: блоки есть почти во всех предметах (нет только у информатики и математики ЕГЭ; у физики после 2025 — фактически тоже нет). Значит «расширить гейт списком» ≈ «список всех» — бессмысленно, а полный снос гейта нарушает просьбу владельца не мешать физикам.

**Решение:** секция доступна всем предметам, но в двух состояниях:
- compact (по умолчанию для всех): одна ghost-строка «+ Блок: общий материал для нескольких заданий» с примером в подписи («перечень веществ для №29–30, текст для №17–20»);
- expanded (как сейчас): при `subjectRequiresCefr(subject) || blocks.length > 0`.

Предикат остаётся каноническим, локальных списков предметов не появляется. Плата: +1 строка в редакторе у физика.

### 2.8 Терминология

Пользовательская модель Егора («задание с несколькими вопросами») и техническая («N задач с общим материалом») — РАЗНЫЕ вещи, и техническую менять нельзя: балл, `check_mode`, resync totals, heatmap, прогресс висят на задаче (см. «что не делать» в промпте). Причём запрос Егора частично уже закрыт другой фичей: «одно задание с подвопросами и общим баллом» — это задача с `grading_criteria_json` (критерии), так и отвечаем.

Нейминг:
- Репетитору: **«Блок заданий»**, подпись-расшифровка «общий материал + несколько вопросов». Формулировку Егора использовать в онбординге/тултипе, но не как имя сущности («задание» занято словом task — коллизия в поддержке и промптах).
- Ученику: слово «блок» не показывать вовсе — заголовок материала («Материал к заданиям 5–12» / title блока). Уже так в `TaskBlockHeader`.
- В Банке: бейдж «Блок · N заданий».

## 3. UX

### 3.1 Редактор (пробник и Банк)

Чипы из блока оставляем (единый источник истины — `blockId` в задаче), но на 29 задачах текущая реализация слабеет: до 10 блоков × 29 чипов = ~300 кнопок, подписанных «#7» (у DELF нет КИМ — чип неинформативен). Инкрементальные правки:

1. **Чип несёт превью вопроса** — title = первые ~40 символов `stripLatex(task_text)`; на десктопе тултип.
2. **Привязка диапазоном** — «№ от [5] до [12] → Привязать»: все группы ФИПИ смежные (подтверждено таблицей), это основной жест. Чипы остаются для точечных правок.
3. **Обратная привязка с карточки задачи** — read-only бейдж блока становится селектом «Блок: —/Блок 1/Блок 2» (репетитор привязывает там, где видит текст задачи).
4. **Авто-предложение блока (killer-фича миграции живых данных):** детект ≥2 задач с одинаковым началом (префикс ~60 симв.) → баннер «Эти 7 задач начинаются одинаково — вынести общее начало в блок?» → одним действием создаётся блок, общий префикс переезжает в instruction, из задач вырезается. Это единственный реалистичный способ конвертировать 90 существующих задач и вариант Эмилии — руками никто не будет.

```
┌ Блок 1 · [Compréhension écrite — Exercice 2   ] ⋮ ✕ ┐
│ Инструкция [ Lisez l'article «APPRENDRE…»      ] 8000│
│ Материал:   [📷 Фото]  [🎧 Аудио]  [📄 Транскрипт]   │
│ Задачи блока:  [5·Selon l'aut…][6·Quel est…][7·…]    │
│ Привязать диапазон:  с [5] по [9]  [Привязать]       │
│ ⚠ Несмежные привязки: 5, 7, 9 — ученик увидит        │
│   три шапки материала                                 │
└──────────────────────────────────────────────────────┘
```

В **конструкторе ДЗ своего редактора блоков НЕ появляется** (итог самокритики, см. 3.5): блок попадает в ДЗ только импортом из Банка или AI-загрузчиком. Конструктор ДЗ — хроническая риск-зона (QA-гейт rule 40), добавлять в него секцию ради редкого сценария «руками собрать блок прямо в ДЗ» — худший размен.

### 3.2 Ученик (пробник)

Текущее (статика: инструкция+фото; sticky: заголовок+аудио) прошло ревью 5.6 — не трогаем. Добавить одно: **длинный текст сворачивается**. Материал > ~1200 символов → показываются первые ~500 с градиентом «ниже есть ещё» + «Читать целиком» (разворот на месте, НЕ модалка и НЕ отдельный экран — к материалу возвращаются на каждом вопросе). Потолок свёрнутого состояния — от `--vv-h`, не `dvh` (rule 80, Safari 15.0–15.3); паттерн `useHasMoreBelow` уже есть в `ProblemContext`. Двухколонку на md+ (материал слева sticky, вопросы справа) — отложить: `StudentMockExam.tsx` и так 2255 строк, ценность не доказана.

### 3.3 ДЗ (guided-чат) — Этап 2

Материал = расширение существующего `ProblemContext` (контейнер условия), НЕ новый элемент экрана:

```
┌ Задача 7 из 11 · Материал блока ▸ (свёрнут)      ┐   ← строка-тогл
│ [🎧 ▶ 0:00 / 23:46]  ← плеер виден всегда,       │
│                         если у блока есть аудио   │
│ ─ Условие задачи ─────────────────────────────    │
│ Selon l'auteur, pourquoi … ?                      │
└───────────────────────────────────────────────────┘
```

- Первая задача блока → материал развёрнут; следующие задачи того же блока → свёрнут в строку (состояние в sessionStorage на assignment+block).
- Материал живёт ВНУТРИ scrollBody условия — класс бага Глеба (блок переменной длины без своего скролла над лентой) не воспроизводить; лучше дождаться редизайна «единый скролл» (вариант 1а, ветка `feat/hw-problem-single-scroll`) и класть блоки уже на него.
- **Все 3 AI-пути обязаны получать материал**: `buildCheckPrompt`/`buildHintPrompt`/`chat` — секция «МАТЕРИАЛ БЛОКА» (instruction + image inline + для аудирования транскрипт server-side, только в грейдинг). Без этого AI проверяет вопрос «по тексту», не видя текста — галлюцинация гарантирована. Это тот же класс, что `storage://`-резолв картинок.
- Квота/логирование не меняются (материал — контекст, не новый AI-путь).

### 3.4 Банк заданий

- Внутри папки/темы задачи одного блока рендерятся группой с шапкой-материалом (реюз render-prop паттерна `CatalogTaskGroups`; шапка сворачиваемая).
- Карточка задачи в поиске/вне группы: бейдж «Блок · вопрос 3 из 6» + первая строка материала серым; клик по бейджу → группа целиком. Поиск не ломается: материал в `kb_blocks`, текст задачи ищется как раньше (в индекс поиска материал НЕ добавляем в v1 — иначе все 6 задач блока матчатся по каждому слову материала).
- «+ из БЗ» и «В ДЗ» при задаче с блоком: выбор «Весь блок (6)» / «Только эту».
- Fingerprint-дедуп: fingerprint задачи НЕ включает материал блока (иначе перенос задачи между блоками менял бы fingerprint и ломал дедуп). Одинаковые вопросы к разным материалам — редкость, риск принят.

### 3.5 Самокритика (скилл critique, применён к предложению выше)

Скоринг по Нильсену (только значимые строки; это бумажный дизайн, не живой UI):

| Эвристика | Балл | Комментарий |
|---|---|---|
| Consistency | 4 | всё — реюз существующих паттернов (снимки, чипы, render-prop, scrollBody) |
| Error prevention | 3 | path B-фолбэк спасает от тихой потери; несмежные привязки — предупреждение |
| Recognition vs recall | 2→3 | исходные чипы «#7» — чистый recall; исправлено превью-текстом и range-вводом |
| Minimalist | 2→4 | исходно тянул редактор блоков и в конструктор ДЗ; после критики — ДЗ получает блоки только импортом |
| Flexibility | 3 | range + чипы + обратная привязка; авто-предложение блока — accelerator |

Найденные собой проблемы и что с ними сделано:
- **[P0] Конструктор ДЗ перегружен** (L0/L1 и так на пределе, хроническая регресс-зона) → редактор блоков в ДЗ убран из скоупа вовсе.
- **[P1] Чипы не масштабируются на 29 задач** → range-привязка + превью-текст.
- **[P1] Ульяна не найдёт compact-строку** (химия не CEFR) → подпись с предметным примером «перечень веществ для №29–30»; плюс авто-предложение блока сработает на её 25 задачах само.
- **[P1] Мобильный материал в ДЗ = класс бага Глеба** → материал внутри scrollBody, зависимость от редизайна «единый скролл» названа явно.
- **[P2] Группировка в Банке добавляет визуальный слой не-блочным репетиторам** → группа появляется только при наличии блоков; у остальных — ноль изменений.
- Осталось нерешённым (честно): в пробнике ученик на телефоне при свёрнутом длинном тексте будет постоянно тапать «Читать целиком» ↔ скроллить к вопросу; двухколонка решила бы, но отложена — проверить на первом живом DELF-пробнике.

## 5. План этапами

**Этап 0 — снять гейт (дни, ноль схемы).** Compact-строка секции блоков для всех предметов в редакторе вариантов + превью-текст в чипах + range-привязка + memo-фикс редактора. Ценность сразу: Ульяна (химия 29–30), Милада (Часть 2), русский/история. Плюс замер adoption Эмилии в её окне 1–5.
**Этап 1 — Банк (основной).** `kb_blocks` + `kb_tasks.block_id` + группировка UI + «Весь блок / только эту» в пикере и корзине + AI-загрузчик распознаёт блоки + Банк→вариант снимком + авто-предложение «склеить дубли в блок» (миграция живых данных Ульяны/Дианы/Эмилии).
**Этап 2 — ДЗ.** Снимок блоков на assignment (student-safe + tutor-only транскрипты) + guided-чат UX + материал во все 3 AI-пути + push-to-kb/авто-зеркало обратно + ссылочные шаблоны. Желательно после редизайна «единый скролл» мобильного экрана задачи.
**Этап 3 — по сигналу спроса.** Каталожная публикация блоков (source→copy), полноценный path B, двухколонка ученика md+, cross-chunk merge в загрузчике, blob-copy аудио.

**Что НЕ делать:**
- НЕ вложенные блоки — в экзаменах вложенности нет; многоподвопросные задания = критерии (уже есть).
- НЕ «одна задача с несколькими вопросами» как сущность — переписывание чекеров Части 1 (7 режимов × 2 зеркала + parity-тест), `mock_exam_resync_attempt_totals`, heatmap, `computeFinalScore`-цепочки, аналитики прогресса и «% самостоятельности»; выгода — только терминологическая.
- НЕ миграция пробничного JSONB в таблицу (0 живых данных, ревью пройдено).
- НЕ редактор блоков в конструкторе ДЗ и HWDrawer.
- НЕ материал блока в поисковый индекс Банка (v1).

## 6. Риски и как узнать раньше

1. **Adoption: фича может не взлететь и в пробниках.** 0 использований за 2 дня — рано судить, но окно Эмилии 1–5 августа = естественный эксперимент. Проверка 6 августа: `SELECT task_blocks_json FROM mock_exam_variants WHERE owner_id=<Эмилия>`. Пусто → сначала чинить редактор (авто-предложение блока, Этап 0/1), а не расширять домены.
2. **AI-загрузчик не соберёт блоки через границы чанков** (текст англ. 12–18 = 1–2 страницы + 7 вопросов, чанк = 2 страницы). Выяснится на первом реальном PDF DELF/англ.; метрика — доля блоков без ручного объединения. Если <50% — поднимать `CHUNK_IMAGES` для языковых или двухпроходный extract, это дороже.
3. **Эмилии может понадобиться «один материал → разные наборы вопросов в разных вариантах»** (переиспользование корпуса). Снимковая модель это уже даёт (снимок независим), а вот правка материала «сразу везде» — нет. Сигнал: просьба «исправь опечатку в тексте во всех вариантах». Решается аддитивно (resync по провенансу), не закладываемся.
4. **Блоки в ДЗ на мобильном** — прямой риск повторения P0 Глеба. Митигция: Этап 2 после редизайна «единый скролл»; материал только внутри scrollBody.
5. **Грант-модель `homework_tutor_assignments`** не проверена (см. 2.5) — проверить ДО миграции Этапа 2, иначе транскрипт утечёт прямым PostgREST.
6. **Номера заданий со «средней» уверенностью** (история, биология, география ОГЭ 2026) — сверить с предметниками (Милада/Полина/Диана) до того, как они попадут в подписи UI или карты профилей. В код Этапов 0–1 номера не зашиваются — риск ограничен текстами-подсказками.

## 7. Решения владельца (2026-08-02)

1. **Этап 0 — отдельно и немедленно.**
2. **Транскрипт аудио в ДЗ — reveal после завершения работы** (модель самостоятельной, state-aware): хранение tutor-only (`block_transcripts_json` не гранится), student-endpoint отдаёт ТОЛЬКО при `thread.status='completed'` — паттерн `fetchStudentThread(workMode)` / `stripIndependentPreRevealFields`. НЕ «tutor-only навсегда» и НЕ безусловный post-submit пробников.
3. **Каталог — по сигналу** (Этап 3).
4. **Авто-склейка дублей в блок — Этап 1.**
5. **Path B — инлайн-фолбэк** (degrade-not-block).
6. **Ответ Егору про подвопросы:** «одно задание с подвопросами и общим баллом = задача с критериями, уже есть»; под-нумерацию не строим. Уточнено предложением Егора — см. §8.

## 8. Челлендж предложения Егора («одно задание с форматом проверки "блок вопросов", как в Фоксфорде»)

**Предложение (скриншот 2026-08-02):** блок = ОДНО задание; внутри — общее условие, затем вопрос → поле ответа (у поля свой формат проверки и верный ответ), вопрос → поле…; КИМ у задания — диапазон (напр. 22–26); неделимо перемещается между папками; общее решение; самостоятельность считается на задание целиком. Нужен в олимпиадной физике, ДЗ, Банке, AI-загрузке.

**Где Егор прав (принимаем в требования):**
- **Неделимость перемещения** — блок обязан перемещаться/удаляться/выдаваться как целое. В модели блоков это UX-контракт, не форма хранения: операции над блоком целиком (перенос задачи блока предлагает перенести весь блок; «В ДЗ» — «весь блок»). Принято в Этап 1.
- **Желаемый UI ученика** («общее условие → вопрос+поле → вопрос+поле») — это ровно то, как блок УЖЕ выглядит на студенческой поверхности пробника (шапка материала + задачи с полями). Расхождение только в том, что под капотом: одна задача или N задач.
- **Олимпиадная многопунктовая задача** (пункты а/б/в, взаимосвязаны, одно общее решение) — реальный кейс, который блоками закрывается ПЛОХО: деление пунктов на отдельные задачи рвёт общее решение (AI проверяет б), не видя решения а)) и ломает олимпиадный инвариант `difficulty === primary_score` (балл на ЗАДАЧУ, не на пункт).

**Где предложение фактически дороже, а не «меньше изменений» (цифры).** «Одно задание с полями» как универсальная модель означает: балл, режим проверки и статистика перестают висеть на задаче. Придётся переписать минимум 10 подсистем, включая оба Deno/browser-зеркала грейдинга:
1. Чекеры Части 1: `src/lib/mockExamPart1Checker.ts` + `_shared/mock-exam-part1-checker.ts` (8 режимов, контракт «задача → один ответ → один режим») + parity-тест smoke §15.
2. `mock_exam_attempt_part1_answers` (строка = КИМ) + OCR бланков (клетка = КИМ) + derive-on-read в двух edge.
3. `mock_exam_resync_attempt_totals` + инвариант STORED `total_score`.
4. Heatmap ДЗ (ячейка = задача), `handleGetResults.task_scores`, drill-down.
5. `computeFinalScore`-цепочка + её SQL-дубли в `hw_tutor_force_complete_task` / `hw_tutor_review_task` (`20260725150000`).
6. «% самостоятельности»: `resolveIndependencePct`, `ai_help_events` per task, 8 SELECT-листов (инцидент 2026-07-27 — цена одного пропущенного).
7. Прогресс/отчёт родителю (`student-progress-build`), review-очередь (`isStudentWorkFullyReviewed`).
8. Guided-чат: тред/`task_states`/StepIndicator ключуются `task_id`, «одна задача = один шаг».
9. Структурные тесты `options_json` (балл кодом — на задаче).
10. Двойной write-path, шаблоны, словари Банка.
«В Фоксфорде так сделано» ≈ у них проверка изначально поле-центрична; у нас полгода инвестиций в задача-центричный грейдинг — смена оси затрагивает всё выше. КИМ-«диапазон 22–26» дополнительно ломает карты режимов/баллов по номеру (у Милады/физики они ключуются одним КИМ); диапазон нужен только как ПОДПИСЬ — блок выводит её из привязанных задач.

**Синтез — три кирпича вместо одного, каждый под свой случай:**
| Кирпич | Что это | Покрывает | Статус |
|---|---|---|---|
| **Блок** | общий материал + N НЕЗАВИСИМЫХ заданий (свой балл/КИМ/режим у каждого) | экзаменационные группы: русский 23–26, химия 29–30, общество 17–20, DELF, аудирование | в проде (пробники), Этапы 0–2 |
| **Задача с критериями** | одно задание, AI-балл по пунктам, общее решение | биология ОГЭ 24–26, сочинения, олимпиадные с развёрнутыми пунктами | уже есть (`grading_criteria_json`) |
| **Задача с подответами** (новое, отдельная спека) | одно задание: общее условие + поля а/б/в, у каждого свой верный ответ и формат, балл = Σ кодом; самостоятельность/перемещение/решение — на задачу целиком | олимпиадная физика с численными пунктами; «блок вопросов» Фоксфорда | предлагается как аддитив (`sub_answers_json` на задаче), Этап ~2.5; UI = скетч Егора 1:1 |
«Задача с подответами» закрывает 100% аргументов Егора (неделимость, общее решение, самостоятельность целиком, поля с форматами) — не трогая ни чекеры пробников, ни heatmap: снаружи это ОДНА задача с одним итоговым баллом; подответы — внутренняя структура её проверки (расширение механики `options_json`: балл считает код, AI только объясняет). Комбинируется с блоками: блок может содержать такую задачу.

**Риск синтеза:** три сущности рядом («блок», «критерии», «подответы») — потенциальная путаница у репетиторов. Митигция: в UI конструктора это ОДИН выбор «формат проверки» (подответы = ещё один пункт селектора), а блок — про материал, живёт в другом месте формы; в онбординге — таблица «когда что».

**Решения владельца по синтезу (2026-08-02, второй раунд):**
1. Показать Егору макет «задачи с несколькими вопросами» — если узнает свою картинку, спор о терминах закрыт. Макет: `docs/discovery/prototypes/task-sub-questions-mockup.html` (артефакт опубликован).
2. Порядок этапов подтверждён: Банк (Этап 1) → ДЗ (Этап 2).
3. «Задача с подответами»: спека + макет сейчас, реализация после Этапа 1. Спека: `docs/delivery/features/task-sub-questions/spec.md`.

**ИСХОД (2026-08-02, после трёх раундов с Егором): «три кирпича» схлопнулись в ДВА.** Требования Егора (отправка/проверка/самостоятельность/столбик — по каждому вопросу, КИМ последовательно, «вопросы = отдельные задачи») стёрли причины для отдельной механики подответов: `sub_answers_json` ОТМЕНЁН, «Задание с несколькими вопросами» = UI-обёртка над группой обычных задач (модель блока) + визард, КИМ-диапазон-сахар, групповые колонки heatmap со сворачиванием. Гейт разбора отменён (разбор = `ai_help_events` вопроса; экзаменационный порядок = `work_mode='independent'`), решения per-вопрос + «один листок ко всем». Спека **v1.0 УТВЕРЖДЕНА** (Егор: «Мечта просто», 12:20), макет v4 = референс UI. Кирпичи: (1) блок/задание с вопросами, (2) задача с критериями (один ответ на все пункты).
