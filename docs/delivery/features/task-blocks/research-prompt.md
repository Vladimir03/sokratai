## Что уже сделано (01.08.2026, в проде)

Фича **«Блоки заданий»** — но ТОЛЬКО внутри вариантов пробников и ТОЛЬКО для иностранных языков.

**Определение:** блок = `{название, текст-инструкция, фото, аудио}` + N привязанных задач. Аудио — один из видов материала, не отдельная механика. Блок **без привязанных задач** = материал на всю работу.

**Схема (изучи миграции целиком):**
- `supabase/migrations/20260801100000_mock_exam_task_blocks.sql`
- `supabase/migrations/20260801100100_mock_exam_variants_block_grants.sql`
- `supabase/migrations/20260801120000_mock_exam_variant_revision.sql`

```
mock_exam_variants.task_blocks_json        jsonb  -- [{id,title,instruction,image_url,audio_url}] — STUDENT-SAFE
mock_exam_variants.block_transcripts_json  jsonb  -- {blockId: текст} — TUTOR-ONLY, НЕ гранится
mock_exam_variants.content_revision        int    -- CAS против stale-клиента
mock_exam_variant_tasks.block_id           text   -- ссылка на элемент JSONB
```

## Задача 1. Предметный ресёрч

Выясни для КАЖДОГО предмета, где в экзамене есть «общий материал + группа вопросов», и как он устроен.

Что именно нужно по каждому предмету:
- номера заданий, объединённых общим материалом (ЕГЭ и ОГЭ отдельно);
- **тип материала**: сплошной текст / таблица / график / изображение / список веществ / аудио;
- объём материала (абзац? страница? 3 минуты записи?);
- сколько вопросов на один материал;
- есть ли **вложенность** (материал → подматериал → вопросы);
- нужен ли материал ученику **во время** ответа или только для чтения перед;
- **разный ли формат ответа** внутри одного блока (тест + развёрнутый вместе).

Предметы, которые заведены в реестре: `src/lib/subjects/registry.ts` — пройди по нему, не по памяти.

Источники, в порядке надёжности:
1. **Прод-база** — реальные варианты и задачи. Через Lovable MCP `query_database` (project `5fbe4a32-1baf-47b0-8f47-83e3060cf929`). Посмотри `mock_exam_variants` + `mock_exam_variant_tasks` + `kb_tasks`: найди задачи с ДУБЛИРУЮЩИМСЯ началом `task_text` — это и есть блоки, которые репетиторы уже собирают руками. Оцени масштаб дублирования по предметам.
2. `docs/` и `.claude/skills/` — уже собранная предметная фактура (карты режимов проверки, `examProfiles.ts`, ФИПИ-таблицы Милады).
3. Демоверсии/спецификации ФИПИ — если нужны номера заданий.

**Итог задачи 1:** таблица «предмет × экзамен → где блоки, какой материал, сколько вопросов» + **оценка, сколько существующих задач в нашей базе выиграли бы от блоков** (это цифра для приоритизации, а не украшение).

## Задача 2. Архитектурные развилки — дай решение по каждой

Это главное. По каждой развилке: варианты, что выбираешь, **чем платим**.

1. **Где живёт блок.** Остаётся внутри варианта пробника (как сейчас) / становится общей сущностью для пробников + Банка + ДЗ / отдельная сущность на каждый домен?
2. **Форма хранения.** JSONB на родителе (сейчас) vs отдельная таблица `blocks` + FK? Что даёт FK, чего стоит миграция уже живых данных?
3. **Перенос между доменами.** Задача из блока едет в Банк, потом в ДЗ. Что происходит с материалом? Сейчас есть пути: push-to-kb, «+ из БЗ» в конструкторе, «В ДЗ» с карточки, шаблоны, `copyTaskToFolder`. Изучи их (rule 40 «двойной write-path», skill `kb-module`) и скажи, где материал теряется.
4. **Одиночная задача из блока.** Репетитор берёт в ДЗ ОДИН вопрос из блока на 8 вопросов. Материал едет с ним? Дублируется в условие? Не едет вовсе?
5. **Anti-leak при переносе.** Транскрипт аудио = ответы аудирования. В пробниках он в отдельной негранимой колонке. Как хранить в Банке и в ДЗ, чтобы не утёк? В ДЗ модель другая: там `solution_text` tutor-only **навсегда** (rule 40), а в пробниках reveal **post-submit** (rule 45). Что из этого применимо к транскрипту?
6. **AI-загрузчик.** Как распознавать блок в PDF (общий текст + вопросы под ним) и давать его править? Изучи `src/components/kb/AiTaskLoader/` и `kb-ai-extract`. Что меняется в промпте, в схеме ответа модели, в UI ревью?
7. **Предметный гейт.** Снять полностью / расширить списком / оставить с компактным видом у неязыковых? Учти: владелец просил гейт, чтобы секция не мешала физикам.
8. **Терминология.** Егор предлагает называть это «задание с несколькими вопросами». Совпадает ли пользовательская модель с технической, и как назвать в UI.

## Задача 3. UX

Спроектируй и покажи (текстом + ASCII-макетом или схемой):

- **Редактор.** Как репетитор создаёт блок, привязывает вопросы, меняет порядок. Сейчас привязка идёт чипами ИЗ блока — оцени, работает ли это на 29 задачах, предложи лучше, если видишь.
- **Ученик.** Как показывать материал: над группой, sticky, в две колонки, сворачиваемо? Отдельно продумай **длинный текст** (статья на страницу) на телефоне и **аудио** (к нему возвращаются на каждом вопросе).
- **ДЗ.** Как блок выглядит в guided-чате ДЗ, где ученик идёт по одной задаче за раз. Это принципиально другой контейнер, чем пробник, — материал придётся показывать на каждом шаге?
- **Банк заданий.** Как выглядит карточка задачи, входящей в блок; как не сломать поиск и превью.

Оцени свою же работу критически: где решение усложняет жизнь репетитору, который блоками не пользуется.

## Задача 4. Перфоманс — критерии, не лозунги

Сформулируй измеримые критерии и проверь текущую реализацию против них:
- вес страницы при N блоках с медиа (у Эмилии до 3 треков × 20 МБ) — что реально качается при открытии;
- сколько запросов к storage на подпись URL, параллельно ли;
- дублирование текста материала: если блок в JSONB и задача копируется в ДЗ — сколько копий текста в базе;
- ре-рендеры редактора при 29 задачах и чипах в каждом блоке;
- лимит PostgREST 1000 строк и пагинация, если блоки станут отдельной таблицей.

## Инварианты платформы (нарушение = стоп)

Прочитай `AGENTS.md`, `.claude/rules/40-homework-system.md`, `.claude/rules/45-mock-exams.md`, `.claude/rules/50-kb-module.md`. Кратко, чтобы не «улучшить» намеренное:

1. **Anti-leak — три слоя.** RLS фильтрует строки, не колонки; от прямого PostgREST защищает только **column-GRANT whitelist**. Новая колонка → явное решение student-safe / tutor-only + миграция гранта.
2. **ДЗ и пробники имеют ПРОТИВОПОЛОЖНЫЕ правила раскрытия.** ДЗ: `solution_text` tutor-only навсегда. Пробники: reveal post-submit — это ценность продукта, а не утечка.
3. **Единственный write-path** вариантов — edge `mock-exam-tutor-api` + атомарные RPC. У `homework_tutor_tasks` **два** write-path (edge и прямой клиентский) — новое поле нужно писать в оба, иначе фича молча ломается через один флоу.
4. **Безопасность RU-обхода.** Хардкод `api.sokratai.ru` намеренный; `*.supabase.co` в клиентском коде — блокер мержа.
5. **Safari 15 / iOS 15 — официальный минимум** (половина учеников в WKWebView внутри Telegram). Запрещены lookbehind в клиентских regexp, `structuredClone`, `Array.at`, `Object.hasOwn`, `overflow: clip`, `dvh` как единственная единица. Инпуты 16px, иначе iOS зумит.
6. **Предметность гейтится каноническим предикатом** (`subjectRequiresCefr`, `getExamProfile`), никогда списком `['french','english',…]` — расхождение таких списков уже ломало создание ДЗ.
7. **Миграции аддитивные.** Нельзя менять применённые миграции, дропать и переименовывать колонки.
