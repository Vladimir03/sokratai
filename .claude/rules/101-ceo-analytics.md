# CEO-аналитика `/admin` — инварианты (всегда в контексте)

**Глубина — skill `ceo-analytics`** («Пульс» и его компоненты, каналы атрибуции, вкладка «Аналитика» и ретеншн, пре-воронка Яндекс.Метрики и готчи целей, Telegram-дайджест, рефералка v1, состав вкладок).

## Источник правды воронки — ДОМЕННЫЕ таблицы, не `analytics_events`

`analytics_events` пишется только с 2026-07-01 → старые когорты в ней невидимы. События нужны для будущих точных дат и канала, **не для стадий**.

Вся агрегация «Пульса» — в `supabase/functions/_shared/ceo-pulse.ts::computePulse(db, now)`, **не в edge-хендлере** (Telegram-дайджест переиспользует ту же функцию). Edge `admin-ceo-dashboard` — тонкая обёртка.

**Клиентское зеркало типов — `src/components/admin/pulse/pulseTypes.ts`** (Deno-модуль не импортируется в браузер). **Меняешь shape → правь ОБА файла.**

## Воронка: 6 поведенческих ступеней + 2 НЕЗАВИСИМЫЕ коммерческие

`PulseTutor.stage` = 1..6 (`registered` → `student_added` → `hw_created` → `hw_sent` → `student_opened` → `student_submitted`), max-достигнутое, счёт «дошло ≥ k» монотонен.

⚠️ **Триал/оплата НИКОГДА не входят в `max(stage)`.** `trial_ends_at` выдаётся при регистрации автоматически → иначе репетитор без единого ученика получал бы stage=7 и «проходил» всю продуктовую воронку (P0 ревью). Ступени `trial`/`paid` — исторические факты (`trialEverIds`/`paidEverIds`), монотонность с 1..6 НЕ гарантируется намеренно.

**Новый сигнал активации** → решить явно: поведенческий (в 1..6, монотонно) или коммерческий/статусный (независимый счётчик).

**FK-дрейф (rule 60) обязателен:** ученик → `tutor_students.tutor_id = tutors.id`; ДЗ → `homework_tutor_assignments.tutor_id = auth.users.id`. У `homework_tutor_student_assignments` **НЕТ `created_at`** (использовать `COALESCE(hsa.notified_at, assignment.created_at)`).

## Каналы — только исторические факты

`reachedValue` (stage ≥ 6) + `paidEver` (реальный `payments`, ручные гранты исключены). Текущий `isTrial`/`isPaying` как «конверсия канала» **ЗАПРЕЩЁН**: авто-триал ≠ конверсия, оплативший исчезал бы из trials, ручной грант выглядел бы оплатой.

Нет строки `profiles` → канал `unknown` «Без атрибуции», **НЕ «Органика»** (иначе дрейф данных «улучшает» органику). Приоритет: referral > egor/promo > utm > web.

## MRR = run-rate, не выручка

Σ **NET**-суммы последнего succeeded-платежа `plan='tutor_ai_start'` каждого репетитора за 35 дней, где `net = amount − refunded_amount` (clamp на 0). Ручные гранты **не** в MRR. Δ — сравнение двух rolling-снапшотов, подписывать «Δ run-rate», **не «за неделю»**.

⚠️ **`mrrAt` SELECT'ит `payments.refunded_amount` → миграция ОБЯЗАНА быть применена до деплоя edge**, иначе PostgREST «column does not exist» уронит весь Пульс.

## Пагинация обязательна + стабильный `.order()`

**PostgREST молча режет на 1000 строк**, а offset-страницы без детерминированного порядка дублируют/теряют строки на границах. Любая новая выборка в `ceo-pulse.ts` / `admin-analytics` → `fetchAll` + `.order('id')` (или `created_at, id`).

## Вкладка «Аналитика»

- **Активность = AI-чат ученика ∪ треды ДЗ.** Раньше видела только AI-чат → репетиторы, работающие в ДЗ, числились неактивными. Новый источник активности (напр. чат репетитор↔ученик) → добавлять в `fetchActivityInRange`, а не считать отдельно.
- **Все календарные бакеты — МОСКОВСКИЕ** (`mskDay()`, UTC+3 без DST). Клиент шлёт `format(date,'yyyy-MM-dd')`, **НЕ `toISOString()`** (в МСК полночь 15-го = 14-е UTC → весь диапазон уезжал на день).
- **Ретеншн/воронка — только само-зарегистрированные:** `registration_source='manual'` (плейсхолдеры репетитора) исключены — их `created_at` = дата заведения карточки, они хоронили D1/D7. В графике регистраций остаются.
- Когорта зрелая **только после ЗАВЕРШЕНИЯ** целевого дня, иначе идущий день читался как финальные 0%.
- Формулы дублируются в tooltip'ах фронта — при правке формулы синхронно править текст.
- Новая тяжёлая вкладка → гейт на активную вкладку (Пульс должен открываться мгновенно).
