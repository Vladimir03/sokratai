# Mock Exams — инварианты (всегда в контексте)

Здесь ТОЛЬКО первично-нарушаемое. **Глубина — skill `mock-exams`** (AI-грейдер Части 2, OCR бланков, режимы проверки по предметам, репетиторские варианты и CRUD, пауза/мульти-сессия, ExamProfile registry, шкалы, курирование Ч2, сиды вариантов).

## Anti-leak — STATE-AWARE, НЕ копировать модель ДЗ

Reveal зависит от `attempt.status`. Это **не** «никогда не показывать ученику»:

| Статус | Что раскрывается |
|---|---|
| `in_progress` / `paused` | **ничего**; result-endpoint отказывает (409/410). `correct_answer` не должен попасть даже в память процесса |
| `submitted` / `ai_checking` / `awaiting_review` | Часть 1 (`correct_answer`, `kim_number`) + предварительный AI-балл и `feedback` Части 2 |
| `approved` | Часть 2 полностью (`solution_text`, `tutor_score`, `tutor_comment`) — **это и есть ценность продукта** |

`ai_draft_json` / `ai_part1_ocr_json` — **никогда** ученику, ни при каком статусе (tutor-only артефакты). Из `ai_draft_json` ученику уходят ТОЛЬКО `suggested_score` и `feedback`; `comment_for_tutor` / `flags` / `elements_check` — нет.

**Контраст с ДЗ:** там `solution_text`/`rubric_*` tutor-only **навсегда** (rule 40). Если ревьюер флагает «утечка solution_text на странице результата» — проверь гейт `status === 'approved'`: post-approval reveal сделан **намеренно**.

**Новый pre-submit статус** ОБЯЗАН попасть в early-reject result-эндпоинта и НЕ попасть в post-submit allowlist (дыра `paused` возникла ровно из этого пропуска).

`mock_exam_variant_tasks` SELECT — **tutor-only** (`is_tutor(auth.uid())`, миграция `20260607130000`). Ученик читал бы `correct_answer` и эталоны Части 2 прямым PostgREST посреди экзамена. Новое клиентское чтение этой таблицы — только tutor-only; студенческие пути идут через service_role edge.

**Аудирование (2026-07-31, DELF Эмилии): ДВА транскрипта с ПРОТИВОПОЛОЖНЫМИ правилами.** `mock_exam_variants.listening_transcript` (транскрипт ТРЕК-УСЛОВИЯ) = ответы аудирования → leak-класс `solution_text`: НЕ селектить на taking/invite-поверхностях, reveal ТОЛЬКО post-submit в result. Само аудио (`listening_audio_url`) — условие, доступно в `in_progress` (signed URL 12ч, `rewriteToProxy`). НЕ путать с транскриптом РЕЧИ УЧЕНИКА (voice-speaking, rule 40) — тот виден ученику всегда (его же речь). Аудио-байты через edge не гонять (22 МБ) — клиент→Storage напрямую, edge только `storage://` ref.

**Блоки заданий (2026-08-01) — общий материал + N вопросов.** Обобщение variant-level трека: блок = `{название, текст-инструкция, фото, аудио}`, аудио — ОДИН ИЗ ВИДОВ материала, не отдельная механика. Блок **без привязанных задач** = материал на всю работу (цельный `integral`-трек). Глубина — skill `mock-exams`.

- ⚠️ **Транскрипты — ОТДЕЛЬНАЯ колонка `block_transcripts_json`, НЕ поле внутри блока.** `task_blocks_json` гранится authenticated (это условие), транскрипты — **никогда**. column-GRANT работает по колонкам; сложишь вместе — отдашь ответы аудирования прямым PostgREST (у назначенного ученика есть row-RLS на строку варианта).
- **`content_revision` + CAS в RPC — обязателен для любого write контента варианта.** Клиент шлёт загруженную ревизию, расхождение → `VARIANT_STALE` (409). Закрывает lost update между вкладками И stale-бандл, который шлёт задачи без `block_id` и молча стирал бы все привязки. Клиент без ревизии отвергается, только если у варианта ЕСТЬ блоки. ⚠️ **ВНУТРЕННИЙ вызов обязан передавать ревизию ЯВНО** (`20260801140000`): `create_with_tasks` вставляет блоки, затем зовёт `replace_tasks` — без `_expected_revision` тот видел «блоки есть, ревизии нет» и рубил СОБСТВЕННУЮ транзакцию (P0 01.08: София потеряла вариант DELF A1 целиком, 8 осиротевших аудиофайлов в бакете; правка существующих вариантов работала, поэтому баг был невидим). Новый серверный вызов write-RPC — тем же именованным аргументом; гард не ослаблять.
- **Секция блоков доступна ВСЕМ предметам** (Этап 0, 2026-08-02): compact-строка по умолчанию, развёрнута при `subjectRequiresCefr(subject) || blocks.length > 0`. Гейт остаётся каноническим предикатом — локальных списков предметов не заводить (AGENTS.md). Плановая модель для ДЗ/Банка и «Задание с несколькими вопросами» — `docs/delivery/features/task-blocks/research.md` + `task-sub-questions/spec.md` (v1.0).
- **Deploy-skew маркер у каждой новой группы полей СВОЙ.** `listening_fields_applied` возвращается захардкоженным `true` с 31.07 и НЕ доказывает поддержку блоков — для них заведён `block_fields_applied`. Новая группа полей → новый маркер, переиспользовать чужой нельзя.
- **Группировка у ученика — по СМЕЖНЫМ задачам одного блока, для ОБЕИХ частей и ОБОИХ `answer_method`.** Скрывать в blank-режиме можно поля ввода, но не материал блока (это условие). «Привязан» считается по всем задачам: иначе блок Части 2 всплывает над Частью 1.

⚠️ **`answer_method='blank'` скрывает ПОЛЯ ВВОДА, а не условия задач (репорт Ульяны 2026-08-02).** Карточки Части 1 рендерились только при `answerMethod === 'form'`, то есть в бланк-режиме исчезал и текст задания с картинками. У физики это маскировал печатный КИМ (чип «Скачать задачи (PDF)»), но у РЕПЕТИТОРСКИХ вариантов `variant_pdf_url` нет никогда — ученик по химии видел пустую Часть 1. То же правило, что для блоков: гейт `answer_method` управляет вводом, никогда — условием. Смежное: способ ответа по умолчанию берётся из `assignment.mode` (репетитор выбрал `form` — не подсовывать бланк), а обещание «официальный бланк ФИПИ» — только там, где PDF реально есть (`physics` × `ege`).
- **Легаси variant-level трек подавляется СЕРВЕРНО при наличии блоков** — backfill кладёт его и в старые поля, и в блок; отдать оба = два плеера и два транскрипта.

## Публичное приглашение → пробник: шаг привязки обязателен

Анонимное прохождение (TASK-12) НЕ реализовано. Лид-форма создаёт попытку с `student_id = NULL`, а `mock-exam-student-api` ищет попытку по `student_id = auth.uid()` — поэтому вести с приглашения ПРЯМО на `/student/mock-exams/:id` нельзя: так каждый, кто заполнил форму, получал «не назначен этому ученику» (репорт 2026-08-02). Между формой и пробником стоит `/p/mock-invite/:slug/start` → вход/регистрация → `POST /share/mock-invite/:slug/claim`.

- **`anonymous_id` — bearer-секрет**, выдаётся ровно раз в ответе `/start`. Без него чужую попытку не присвоить даже зная `attempt_id`.
- ⚠️ **CHECK `mock_exam_attempts_owner_xor`**: привязка обязана ОДНИМ UPDATE ставить `student_id` и обнулять `anonymous_id`. Раздельные апдейты падают на констрейнте.
- ⚠️ **CAS-промах ≠ 404.** Почти всегда это гонка ДВУХ НАШИХ вызовов (экран привязки + фоновый self-heal от одного `INITIAL_SESSION`). Обязательно перечитать строку: `student_id === uid` → `already_claimed`. Иначе ученику говорят «заявка не действует» о попытке, которая уже его. Плюс: self-heal не запускается на claim-роуте, pending-claim чистится ТОЛЬКО на успешных статусах.
- `UNIQUE (assignment_id, student_id)` → `23505` при повторной попытке: не ошибка, ведём в существующую.
- ⚠️ **Копирайт не должен обещать «прохождение без регистрации».** Тексты мастера создания и модалки готовой ссылки говорили это репетитору, он рассылал ссылку с таким обещанием, а лид упирался в форму входа (ревью 5.6 P2). Правка механики без правки текстов — половина работы: ищи обещания в `TutorMockExamCreate` + `LeadLinkSuccessDialog`, а не только на публичной странице.
- **`started_at` анонимной попытки = NULL.** Иначе таймер тикает, пока ученик заводит аккаунт. Следствие: у свежей попытки пусты И `started_at`, И `answer_method` — диалоги выбора показывать ПОСЛЕДОВАТЕЛЬНО, иначе два focus-trap и старт таймера под верхним.

## Варианты — ownership и единственный write-path

- **Единственный write-path вариантов — edge `mock-exam-tutor-api`** (клиентских write-политик/грантов на `mock_exam_variants` / `_variant_tasks` нет). Замена задач — атомарной RPC (`mock_exam_variant_replace_tasks`), не delete+insert из edge.
- **Variant-ownership ОБЯЗАН быть и в `WITH CHECK` назначений.** У authenticated есть ПРЯМЫЕ INSERT/UPDATE-политики на `mock_exam_assignments`, а **FK не применяет RLS целевой таблицы** → без гарда `mock_exam_variant_usable_by()` любой вставлял бы assignment с чужим личным `variant_id` мимо edge и вытягивал `correct_answer` через student-edge. **Любой новый write-path, принимающий `variant_id`, обязан проверять «каталожный ИЛИ мой».**
- `owner_id` (NULL = каталог) — **отдельная колонка от `created_by`**; `ON DELETE RESTRICT`, т.к. `SET NULL` «утёк» бы личный вариант в каталог.
- «Вариант в работе» → контент-правки **блокируются** (409 `VARIANT_IN_USE`); авторитет — гард внутри RPC, а не pre-check в edge.

## AI-грейдер — frozen contract, никогда не автопубликует

- **Frozen JSON shape** (зеркало `src/types/mockExam.ts::MockExamPart2Draft`) — расширять только аддитивно.
- Подтверждение репетитором **обязательно**; AI никогда не публикует ФИНАЛЬНЫЙ балл сам.
- **Машина состояний:** `in_progress → submitted → ai_checking → awaiting_review → approved`. Submit оставляет `submitted`; статус `ai_checking` ставит только CAS-claim грейдера — **никогда напрямую в submit-хендлере**.
- Stale-lock = **120с** во всех 3 callsite (грейдер CAS, `retry-part1-ocr`, `regrade-part2`).
- Bulk Часть 2 **никогда не перезаписывает** строки со `status IN (tutor_approved, tutor_modified)` — только `ai_draft_json`.
- Approve **никогда не блокируется**: отсутствующие баллы авто-занулятся с прозрачным `tutor_comment`.
- Fail-closed по subject: сбой чтения `subject`/`exam_type` варианта → 500, **НЕ** молчаливая деградация к физике (грейдила бы чужой предмет физ-рубрикой).

## `total_score` — STORED, не производное

Инвариант: при непустом значении `total_score = COALESCE(total_part1_score,0) + COALESCE(total_part2_score,0)`.

**Каждая запись пер-задачного балла ОБЯЗАНА вызвать атомарную RPC `mock_exam_resync_attempt_totals(_attempt_id)`** сразу после upsert (хелпер `resyncAttemptTotals`). Inline JS read-sum-update **не возрождать** — он был racy при конкурентных post-approval правках. `manually_entered` исключён (его total вводит репетитор).

## Часть 1 — зеркало чекера и предметные карты

- **Deno-mirror инвариант:** `src/lib/mockExamPart1Checker.ts` ↔ `supabase/functions/_shared/mock-exam-part1-checker.ts` логически идентичны. Симптом дрейфа: «превью говорит верно, финал даёт 0». Гард — `scripts/test-mockexam-checkmode-parity.mjs` (smoke §15).
- Источник истины набора режимов — реестр `MOCK_EXAM_CHECK_MODES`. Добавляя режим: реестр + Deno-зеркало + evaluator в оба диспатча + `CHECK_MODE_OPTIONS` + `VALID_PART1_CHECK_MODES` + OCR-промпты + CHECK-миграция. Пропуск места роняет `npm test`.
- **У каждого предмета СВОЯ карта КИМ→режим.** Никогда не переиспользовать физическую карту для другого предмета: номера пересекаются, критерии разные (обществознание: замена цифры = 0, физика = 1 балл).
- Частичный балл только там, где он есть у ФИПИ — не «протекать» в strict/unordered/task20/pair.
- **Кириллица + `\b` ЗАПРЕЩЕНЫ** в Deno-регэкспах рубрик: JS `\b` ASCII-only, `/\bЕГЭ/` не матчит. Только `hasWord` / `(?<![\p{L}\p{N}])…` с флагом `u` (lookbehind в Deno безопасен, в клиенте — нет, rule 80).

## Разбивка на части — из данных, НЕ окно 21–26 (репорт Ульяны, 2026-08-04)

**Истина — `mock_exam_variant_tasks.part`**; `ExamProfile.part2KimRange` только фолбэк отображения. Резолвер — `src/lib/mockExamPart2.ts`. Гард — smoke **§27** (запрет литерала `21, 22, 23, 24, 25, 26` и сравнений № КИМ с границей; исключение — `// smoke-allow: kim-window <причина>`).

- Модель — **множество**, не диапазон (у DELF части чередуются). Union задач варианта и строк решений: осиротевшая после правки варианта строка обязана остаться привязываемой, иначе её балл теряется молча. **Пусто → пусто**, физику «по умолчанию» не подставлять — это и был баг.
- Симптом: у химии ОГЭ (Ч2 = 20–23) задание 20 исчезало из ленты привязки фото → AI его не проверял. Тот же класс — persist Части 1 в `mock-exam-grade` шёл по `for (kim = 1..20)`: у химии ЕГЭ (Ч1 = 1–28) задания 21–28 не получили бы OCR-балл.
- Пресид `grouped[kim] = []` обязан идти по тому же набору, что лента чипов («снять привязку» = явный `{kim: []}`). Теплокарта резолвит **обе** части сразу, иначе номер отрисуется дважды.
- Смена предмета в редакторе: баллы/режим — сразу, **разбивка — только по подтверждению** (`planPartSplitForSubjectExam` → диалог). Гейт экзамена один на всех — `resolvePart2Range`.
- **OCR Части 1 — тоже по реальным номерам** (ревью 5.6, 2026-08-04): `sanitizePart1OCRResult(parsed, allowedKims)` + номера в промптах из `tasksMeta`. Иначе модель просят распознать «клетки 1-20», а ключи 21–28 санитайзер ВЫБРАСЫВАЕТ → верно решённые задания химии ЕГЭ молча получают 0. Вызов без `allowedKims` = легаси 1..20 байт-в-байт.
- **`[]` ≠ `undefined`**: `undefined` — старый edge (берём профиль), `[]` — edge авторитетно сказал «Части 2 нет». Подстановка профиля на `[]` рисует ФАНТОМНЫЕ задания, хотя привязка фото ответит `NO_PART2_TASKS`.
- ⚠️ **Физика лояльна к ПУСТОМУ exam, но НЕ к ОГЭ.** `resolvePart2Range` зеркалит `inferPart1CheckMode`: `'' → ege`, `oge → physics:oge` (там `part2KimRange: null` → решает формат проверки). ## Формулы: столбик vs предложение (`preprocessLatex`, 2026-08-04)

Правило «втянуть формулу в предложение» склеивало **любые** две формулы на соседних строках → химик получал строчку и обходился точкой после `$`. Теперь построчно: обе строки формулы (или следующая начинает пункт списка) → перенос сохраняется; иначе прежнее поведение. Хвостовой знак препинания в строке-формуле допускается **намеренно** — иначе поехал бы уже написанный контент. Гард — smoke **§28**.

⚠️ `normalizeBlockPairs` демотит `$$…$$` короче 40 символов в инлайн — короткое уравнение блоком не сделать, не ищи баг в другом месте.
⚠️ **Вставка шаблонов формул — `useInsertAtCursor` с АБСОЛЮТНЫМ диапазоном** (`selectStart`/`selectEnd` в координатах сниппета), не «отступ от конца»: хук может дописать перенос строки перед вставкой, и отсчёт от конца съезжает. Новый шаблон в `EquationButton` → смещения проверять на готовой строке `$tex$` (прогон `katex.renderToString({throwOnError:true})` + печать `$…[выделение]…$`), а не на глаз. Попап обязан гасить И `onOpenAutoFocus`, И `onCloseAutoFocus` — иначе Radix уводит фокус с textarea и сбивает выделение. **Кнопка «Уравнение» с 2026-08-07 живёт НЕ только здесь** — она во всех редакторах задач (конструктор ДЗ, База знаний: создание и редактирование, условие + решение); порядок шаблонов фиксированный (общая математика, ниже группа «Химия»), от предмета НЕ зависит. Список поверхностей — в шапке `EquationButton.tsx`.
⚠️ **mhchem НЕ подключён**: без него `\ce{}` не падает, а молча рисует «ce» курсивом (`\c` — валидный акцент). Шаблоны кнопки «Уравнение» — ванильный KaTeX. Будешь подключать — проверяй в БРАУЗЕРНОЙ сборке: в Node katex резолвится в два инстанса и `__defineMacro` не применяется.
